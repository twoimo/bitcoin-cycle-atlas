# 공모주 캘린더 데이터 규칙

- 원천: 38커뮤니케이션 `http://www.38.co.kr/html/fund/index.htm` 수요예측(o=r)·청약(o=c) 1~2페이지. 인코딩 EUC-KR. 수집 일시와 원본 해시는 JSON의 `수집일시_KST`·`출처`와 플스포 프로젝트 `원본자료/05_공모주_캘린더/`에 기록.
- 스키마: `항목[].종목/수요예측[a,b]/청약[a,b]/확정공모가/희망공모가/공모금액_백만원/일반청약경쟁률/주간사[]`, 날짜는 `YYYY-MM-DD` 또는 null.
- `상태` 필드는 참고용일 뿐, UI는 `ipoStatus()`로 열람 시점 재계산. 재수집 시 상태 문자열을 갱신하지 않아도 화면은 맞다.
- 38 자료는 민간 집계이며 정정·연기가 가능하다. 표는 안내 문구로 이를 표시하고, 실제 청약 판단 근거로 쓰지 않는다. 원페이지의 재배포 제한 안내를 보존한다. 2026-11-01 사용자 결정은 데이터 포함 공개 머지이며, 이는 원저작자 허가 확인과는 별개다.
- 재수집 절차: 38 두 페이지 수집 → EUC-KR 디코딩 → 수요예측/청약 병합(수요예측 우선 마일스톤) → `dist/data/ipo-calendar.json` 갱신 → `node --test tests/ipo-view.test.mjs`.

- 날짜 범위: 시작일부터 종료일까지 포함해 진행 중으로 표시한다. D-day는 예정일 기준이며 진행 중은 D-DAY, 마감은 마지막 종료일 이후 경과일이다.
- 공모금액 원단위는 백만원: 100백만원 = 1억원. 자동 재수집 루틴은 없다.

## 2026-11-01 리베이스 검증 기록

- 기준 main: `9919b71a1e41db8d94bd510d70239467c476a61b`. 공모주 회귀 13개 모두 통과.
- macOS ARM64 / 공식 Node v24.22.2 대조: 기준 main 2,264개 중 2,237 통과·27 실패, 후보 2,277개 중 2,250 통과·동일한 27 실패. 새로 실패한 테스트 이름은 없다.
- 기존 실패는 보존된 Ethereum 예측을 원입력으로 재실행할 때의 정확 일치 검사에 집중된다. 수치 차이의 근본 원인이나 Linux CI 결과는 이 로컬 대조만으로 확정하지 않는다. 모델·원장·허용오차는 수정하지 않았다.
- 정적 경로 검사와 standalone 빌드/정적 검증 통과. 실제 브라우저에서 초기 진입·검색·빈 결과·필터·모바일 가로 넘침을 별도 확인한다.
- 첫 구현 시점의 1,038개 통과는 옛 기준점의 기록이다. 리베이스 후 전체 통과로 오인하지 않는다.

- 원문 날짜 범위의 두 번째 월을 보존해 월 이월 5건을 수정했다. 15개 공모주 회귀 검사에는 전체 일정의 종료일 순서와 잘못된 범위의 거부 경로가 포함된다. 위 2,277개 전체 대조는 이 두 검사 추가 이전 관측이다.

## 디자인 감사 구분

- 새 IPO CSS의 색상 리터럴·간격·대문자 레이블 지적을 공통 토큰과 4px 간격으로 수정했다. 표의 세로 고정은 개별 셀 대신 기존 공통 `thead` 소유 패턴으로 연결하고, 종목명은 가로 방향만 고정한다.
- 원격 `6f5ec14` 감사는 IPO 외 기존 4개 경로에서 `th + th` 또는 `thead + th`를 동일 top:0로 집계했다. 검사기는 숨겨진 요소와 다른 스크롤 소유자도 한 목록에 포함한다. 이를 전체 UI 통과나 확정 오탐으로 처리하지 않으며, 기존 화면의 별도 시각 검토 과제로 남긴다.
- 원격 감사의 8개 선언 경로에는 새 IPO 경로가 없다. IPO 경로는 이 작업의 실제 브라우저 검증으로 별도 확인했으며 전체 감사 범위에 포함된 것으로 주장하지 않는다.

## 월간 격자 (v1.30.1)

- `ipo-month-calendar.js`가 요일 배치·날짜 기간·월 범위·장 이동을 소유한다. 원자료와 상태 계산은 기존 `ipo-view.js`를 유지한다.
- 월별 페이지와 마지막 목록 페이지는 한 스크롤 소유자 `.ipo-pages`의 CSS scroll snap을 사용한다. 휠 이벤트를 가로채거나 새 루틴을 추가하지 않는다.
- 날짜 상세는 native dialog다. 기간에 속하는 모든 종목을 표시하며 실제 영업일·접수 시간으로 추정하지 않는다.
- 4·5·6주 월을 날짜에 맞춰 배치한다. 폭이 좁으면 글자가 줄지만 전체 이름은 날짜 상세와 접근 가능한 이름에 남긴다.
- 480px 이하의 낮은 화면은 강제 절단 대신 최소 높이·proximity snap을 사용한다. 숨겨진 경로의 0 높이는 선택 월을 바꾸지 않는다.

### 로컬 월간 달력 검증

- 날짜·월별 배치 15개 + 기존 공모주 15개 + standalone 6개 + 릴리스 문서 1개, 합계 37개 통과.
- 전체 dist 정적 디자인 감사 FAIL 0 / REFLEX 0 / 기존 WARN 35. 정적 경로 검사 통과.
- 실제 브라우저에서 좌표를 지정한 달력 내부 휠로 12월→11월 스냅, 기본 Space로 달력→목록 스냅, Page Up 이동, 날짜 상세 9종목·Esc 닫기, 검색 필터, 390×844에서 페이지와 각 월 높이 583px 일치(상단 복귀 버튼 높이 조정 전)와 페이지 가로 넘침 없음을 관측했다.
- 임시 진단 스크립트는 원본 준비 HTML 해시와 일치하도록 제거했다. 코드 고정 후 두 번의 재로딩은 ready·오류 0이었지만, 이전 hot-edit 중 간헐적 초기 로딩 오류의 원인까지 확정한 것은 아니다. 공개 배포의 실제 첫 진입을 별도로 확인한다.
- 로컬 전체 2,289개 결과(최종 UI 회귀 5개 추가 전)는 변경 없는 baseline과 같은 기존 macOS Ethereum 재현 실패 27건이었다. 최종 커밋의 전체 통과 여부는 Linux CI로 따로 검증한다.

- 실제 모바일→통합 차트→데스크톱→공모주 복귀에서 마지막 전체 목록(4/4장)이 유지되는 것을 확인했다.
