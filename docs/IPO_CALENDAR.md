# 공모주 캘린더 데이터 규칙

- 원천: 38커뮤니케이션 `http://www.38.co.kr/html/fund/index.htm` 수요예측(o=r)·청약(o=c) 1~2페이지. 인코딩 EUC-KR. 수집 일시와 원본 해시는 JSON의 `수집일시_KST`·`출처`와 플스포 프로젝트 `원본자료/05_공모주_캘린더/`에 기록.
- 스키마: `항목[].종목/수요예측[a,b]/청약[a,b]/확정공모가/희망공모가/공모금액_백만원/일반청약경쟁률/주간사[]`, 날짜는 `YYYY-MM-DD` 또는 null.
- `상태` 필드는 참고용일 뿐, UI는 `ipoStatus()`로 열람 시점 재계산. 재수집 시 상태 문자열을 갱신하지 않아도 화면은 맞다.
- 38 자료는 민간 집계이며 정정·연기가 가능하다. 표는 안내 문구로 이를 표시하고, 실제 청약 판단 근거로 쓰지 않는다. 재배포 금지(개인적 이용 보관).
- 재수집 절차: 38 두 페이지 수집 → EUC-KR 디코딩 → 수요예측/청약 병합(수요예측 우선 마일스톤) → `dist/data/ipo-calendar.json` 갱신 → `node --test tests/ipo-view.test.mjs`.
