# v1.29 · 보존 예측, 검증 가능한 자료와 유동성 모델

## 구현 범위

다섯 단계 고도화를 실제 화면·계산·자료 보존·검증·배포 경로에 연결합니다. v1.28.2의 18개 자산 비교표, 실제 판단 기록과 저장 잠금 보호를 병합해 보존했습니다. BTC 첫 행, 어두운 단일 작업 화면, 모바일의 기본 접힌 지표, 원본 관측값 선택·내보내기와 독립형 HTML도 유지합니다.

비교표는 기존 트레이딩뷰 스타일의 차트와 같은 어두운 배경·버튼·얇은 구분선을 사용하도록 다시 정리했습니다. 제목과 툴바를 압축하고 수익률·판단 상태에만 의미 색상을 남겼습니다. 고정 종목 열, 표 안의 스크롤과 모바일 가로 이동, 판단 이력의 조작은 유지합니다. 320px부터 데스크톱까지 실제 치수와 조작은 [새 테마 검증](evolution-2026-10-26/ui/tradingview-theme/README.md)에 있습니다.

### 1. 보존 기록과 자료 시각

- 입력 스냅샷과 전체 일별 예측 경로를 내용 해시로 보존합니다. 모델 소스, 입력·출력 해시, 시드, 기준일, 생성 시각, 실제 공개 여부를 구분합니다. 재생할 때 현재 모델을 다시 돌려 과거 경로를 바꾸지 않습니다.
- 최초 보존은 2026-10-25 관측 기준의 5개 시나리오입니다. 30·90·180일 목표 15개는 아직 만기가 오지 않아 모두 평가 대기이며, 완료된 전향 평가 수는 0입니다. 당시 공개된 과거 예측을 복원했다는 주장을 하지 않습니다.
- 예약 보존은 새 완료 관측 30개 간격입니다. 모델·설정 변경과 같은 기준일 자료 정정은 예외로 즉시 보존합니다. 원자료 갱신·기존 기록 평가·활성 실험 갱신은 매일 수행합니다. 사용자가 화면에서 실행한 모든 계산을 자동 보관하는 기능은 아닙니다.
- 시장 마감, 비교 가능 시각, 공급자 공개 시각, 실제 수집 시각과 배포 시각을 구분합니다. 모르는 공급자 공개 시각을 마감 시각으로 채우지 않습니다. 지연·보존·결측·상충 상태를 표시하며 공통 기준일은 동시 호가를 뜻하지 않습니다.

### 2. 기록·평가 화면과 시작 성능

- 기존 명령 팔레트와 자료 설명에서 기록·평가·변경·자료·실험·성능의 여섯 탭을 엽니다. 현재 자료를 사용한 기존 판단 이력과 보존 예측 원장은 별도 의미로 유지합니다.
- 원본 기록을 해시 검증한 뒤 재생하고, 정확한 날짜·값 선택, 키보드 이동, 기간 변경, 창 크기 변경과 JSON 저장을 지원합니다. 모바일 날짜 눈금 간격과 비동기 화면 갱신의 포커스 복원을 수정했습니다.
- 비교표의 첫 화면에서 사용하지 않는 차트·연구·내보내기 초기화를 지연합니다. BTC 계산은 가능한 환경에서 실제 모델 Worker로 옮겼으며, 새 요청의 소유권과 자료 버전이 맞아야 화면에 반영합니다. 오프라인과 Worker 실패는 동일한 수치 모델로 계산합니다.
- 제한된 로컬 성능 기록을 조회·저장합니다. 외부로 전송하지 않습니다. 사용자 정의 지연 시간이나 Event Timing 샘플을 INP로 표시하지 않습니다.

### 3. 당시 계산과 변경 설명

- 보존된 전체 경로, 당시 관측과 이후 실제 관측을 구별합니다. 30·90·180일 평가에는 실제 선행 일수, 기준 모형, 모델 버전과 미성숙 목표를 명시합니다.
- 동일 날짜의 로그 가격 변화를 기준선·주기·잔차·나머지로 분해합니다. 정확한 대수적 분해이며 경제적 원인의 증명은 아닙니다.
- 공개 파일 명세는 실제 소스 커밋과 전체 파일 목록·바이트를 검증합니다. 배포 전에 원격 main과 준비한 커밋이 같은지 확인하고, 배포 후 명세와 핵심 파일 네 개를 실제 HTTP 응답으로 확인합니다.

### 4. 부채·우선주와 ETH 유동성

- MSTR의 검토된 여섯 채무 상품을 개별 추적합니다. 결제 이후 해당 쿠폰을 중단하고, 상환과 주식 전환을 구분합니다. 전환은 부채 감소와 주식 증가를 함께 반영합니다. 미확인 비용은 명시적인 잔여 비용 가정으로 둡니다.
- BMNR의 유동 ETH, 스테이킹 ETH, 출금 대기, 보상 대기를 분리합니다. 잠긴 ETH를 즉시 팔아 현금을 만들지 않으며, 지급 부족은 부채·연체에 남깁니다. 출금·보상 지연과 초기 스테이킹 비율은 명시적인 시나리오 가정입니다.
- 재스테이킹하지 않는 보상의 일별 현금 발생 기준을 고정하여 긴 계산 구간과 일별 계산의 결과가 일치하도록 했습니다. 잔고와 풀 합계 불일치, 잘못된 채무 날짜 순서, 부동소수점 잔액으로 발생하던 가짜 유동성 부족도 검증·수정했습니다.
- ETH 화면과 BMNR의 ETH 가격 계산이 같은 조건에서 같은 엔진을 사용합니다. 미래 경로는 일별 선이며 실제 OHLC나 미래 장중 캔들을 만들어내지 않습니다. 현재 2035년 화면 범위의 기본 스트레스 계산에는 유동성 부족이 없습니다. 더 긴 특정 가정의 경로에서 생기는 부족 시점을 확정적인 미래 사건으로 표현하지 않습니다.

### 5. 후보 실험과 채택 판단

- 실제 순차 재계산 549건과 분리된 목표 구간 검토를 수행합니다. 변동성 감쇠 추세, 경험적 오차 구간, 주기 제거 실험은 기준선보다 충분한 개선을 입증하지 못하여 채택하지 않습니다.
- 이번 개발에서 정한 실험 정책은 향후 재현을 위해 버전화합니다. 이미 살펴본 역사 구간에 사전 등록된 정책이나 손대지 않은 검증 집합이라는 명칭을 붙이지 않습니다. 3~5개월 주기 가속 가설이나 확률 보정을 입증했다고 주장하지 않습니다.
- 동일 원자료의 SVG·Canvas 실험에서도 충분한 성능 우위와 기능 동등성이 확인되지 않아 기존 SVG를 유지합니다. Worker와 지연 초기화의 실제 브라우저 측정은 [성능 보고서](PERFORMANCE_EVOLUTION_2026-10-26.md)에 별도로 보존합니다.

## 상태 전이와 검증

공개 상태는 수집→검증→준비→확인으로 이동하며, 바뀐 소스·파일과 다른 공개 응답은 보류 또는 폐기합니다. TLA+ 유한 모델, 의도적으로 제거한 가드의 반례, 실제 코드 변이와 복구 검사를 함께 실행합니다. 새 `verify-publication-state` 프로젝트 스킬과 상태전이도를 추가합니다. 기존 시장·주식·ETH 검증기도 유지합니다. 검증 프로세스가 비정상 종료되었는데 정상적인 반례로 통과하던 오류는 정상 종료 코드·신호를 확인하도록 수정했습니다.

이 검증은 명시된 유한 상태와 코드 가드의 성질을 확인합니다. GitHub의 원격 원자성, 모든 장애, 모든 브라우저 또는 예측 정확도의 전체 증명은 아닙니다. 외부 다른 회사의 세 모델 검토를 수행한 것으로 표시하지 않습니다.
