## 4. 재현 가능한 파이프라인

### 4.1 미디어 입력·변환

`scripts/conference/prepare-media.py`와 `media_config.example.json`을 사용한다. 예제의 미결정·경로·full SHA-256을 실제 승인 입력으로 채운 별도 설정이 필요하다.

```sh
python3 scripts/conference/prepare-media.py --config approved-media.json --out build/conference-media --check
python3 scripts/conference/prepare-media.py --config approved-media.json --out build/conference-media
```

- full SHA-256·R17 승인 해시·290/257쪽·입력 경로·오디오 시각/길이를 확인한 뒤 변환한다.
- 페이지는 `pages/final/0001.webp`, `pages/r17/0001.webp` 형식이다. 긴 변1600~2000px, 품질75~85 범위 내의 명시 설정을 쓴다.
- 오디오는 선택한 m4a/opus, mono32~48kbps, 명시한 세션 또는 청크 경계로 변환한다. 세션이 녹음 경계18000초를 넘으면 물리 파일을 나누되 같은 프로그램 세션을 유지한다.
- 계획 경계 `t0/t1`과 ffprobe 실측 `durationSec`를 분리한다. 인코더 패딩을 숨기거나 파일 길이를 누적해 이벤트 시각을 밀지 않는다.
- 출력 `media-manifest.json`은 자산의 상대 경로·바이트 수·full SHA-256·입력 해시·오디오 실측값을 기록한다.
- preflight 성공은 **변환 성공이 아니다**. `mediaPrepared:false`로 보고한다. 실제 변환 후에도 시각·청취 검수는 별도다.
- 기존 출력 디렉터리를 덮지 않는다. 실패하면 기존 결과를 유지하고 성공 자산으로 표시하지 않는다.

실행 환경은 Python3.10 이상, Pillow의 WebP 지원, Poppler, FFmpeg/ffprobe다. 원자적 게시에는 Linux `renameat2(RENAME_NOREPLACE)`를 사용하므로 macOS/Windows에서는 게시를 명시적으로 거부한다. 현재 Linux 환경만 검증 범위다. `--out`의 부모 디렉터리는 미리 존재해야 하고, 목적지 자체는 없어야 한다.

### 4.2 자막과 타임라인

`scripts/conference/timeline.mjs`, `build-timeline.mjs`, `verify-timeline.mjs`와 `timeline_config.example.json`을 사용한다. 예제는 실제 타임라인이 아니다.

```sh
node scripts/conference/build-timeline.mjs --config approved-timeline.json
node scripts/conference/verify-timeline.mjs --config approved-timeline.json
node scripts/conference/verify-timeline.mjs --config approved-timeline.json --publish-ready
```

기본 생성은 검수 미완료 사유를 가진 초안이 될 수 있다. `--publish-ready`는 입력·검수 영수증 계약을 강화하는 옵션이며, 실제 청취·UI·배포 승인 결과를 뜻하지 않는다. 오디오 분할 enum은 두 설정 모두 `session` / `chunk`다. 보조 장표를 생성하는 선택은 아직 구현하지 않아, 이 변환 도구는 사용자에게 `generatedSlides:false`가 명시적으로 확정된 경우만 지원한다. 값을 자동으로 false로 채우지 않는다.

- 이벤트는 2026-10-31 12:33:00~18:13:00 KST, 길이20400초다. 파일2 시작은 이벤트 기준18000초이며 SRT 내부 시각에 이 오프셋을 더한다.
- `plaud1#<원본 cue ID>` / `plaud2#<원본 cue ID>`로 추적한다. 원문 행·줄바꿈을 보존하고 SRT1개 세그먼트를 합치거나 자르지 않는다.
- 기대 행 수는7995+1174=9169다. 실제 원본 해시·파싱 행 수·source ID 집합을 대조하며 누락·중복·잘못된 시간·범위 밖 페이지를 거부한다.
- 겹치는 cue는 시작 시각 순서가 정상이라면 원문 그대로 유지한다. 각 파일의 자막 끝을 원본 오디오 실측 길이와, 전체 마지막 자막 끝을 분할 오디오 실측 길이 합계와 각각 대조한다. 명목20400초를 실측값으로 표시하지 않는다.
- 프로그램00~14의 실제 경계와 두 덱별 페이지 매핑을 입력으로 받는다. 매핑을 추정해 채우지 않고 미매핑은 null로 보존한다.
- 미디어 입력·프로그램·사람 검수 매핑을 받아 `timeline.json`과 파일별 자막 JSON을 같은 출력 묶음으로 만든다. 입력/출력 경로 충돌과 기존 출력 덮기를 거부한다.
- 초안과 검수 영수증 검사를 구별한다. 검수 영수증이 있다고 해서 도구가 직접 오디오를 들었거나 브라우저를 검증한 것은 아니다. 최종 청취·시각 검수 증거를 별도로 검토해야 한다.

실제 `timeline.json`은 아직 생성하지 않았다. SRT·오디오·PDF·R11 앵커가 없으므로 실제9169행 보존과 덱별 매핑을 검증할 수 없다.

### 4.3 플랫폼 한도와 오디오 탐색

Cloudflare Workers Static Assets의 파일당 최대 크기는 **25 MiB = 26,214,400바이트**다. 무료 플랜 파일 수는 **Worker version당20,000개**이므로 컨퍼런스 파일뿐 아니라 최종 배포 패키지 전체를 세어야 한다.[^cf-limits] `existingAssetCount`는 호출자가 제공한 기존 패키지 개수이며 도구가 운영 자산을 직접 측정했다는 뜻이 아니다. 실제 배포 패키지의 최종 전체 개수·최대 파일 크기는 별도 증거로 남긴다.

기본 정적 자산은 Range 요청에도 전체 파일을200으로 반환한다. 206·Content-Range를 직접 제공하려면 해당 경로를 Worker로 보내는 구현이 필요하며, 이 경로에는 Worker 요청 한도가 적용된다.[^cf-range] 로컬 파일 재생이나 로컬 서버의206응답을 운영 탐색 성공으로 대체하지 않는다. 형식·분할 선택 후 실제 배포 응답, 브라우저 seek, 세션 경계에서의 지속 재생을 확인한다.

## 6. 재개 조건과 다음 순서

1. 최소 세트(PDF2개·SRT2개·40분짜리 오디오2)와 R17 최종본/오디오/화자/보조 장표/라우팅 선택을 받는다. 전체 변환·재생 완료에는 5시간짜리 오디오1 전체와 R11 대조 자료도 필요하다. 요청서가 허용한 오디오1의5분 샘플은 초기 청취 확인용이며 전체 음성 검증을 대체하지 않는다.
2. 실제 파일 full SHA-256을 계산해 승인본을 고정하고, 페이지·오디오 변환을 실행한다. 용량·길이·이미지 품질을 실측한다.
3. R11 앵커와 장표/자막 텍스트로 매핑 초안을 만든 뒤 사람 검수와10지점 청취를 수행한다. 실제 `timeline.json`을 커밋한다.
4. 그 타임라인으로 기존 셸 안에 플레이어를 구현하고 동기화·딥링크·접근성을 검증한다.
5. 6뷰포트·4G·1시간 재생·기존 게이트를 수행한다. 사용자 승인 없는 main push/merge/배포는 하지 않는다.
