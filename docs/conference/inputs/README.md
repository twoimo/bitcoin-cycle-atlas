# WP-A 입력 번들 (P1b 타임라인·매핑용)

`docs/conference/deck-lock-20261112.json`이 고정한 원본 덱과 전사본에서 **읽기만** 해서 만든 입력이다. 덱·전사본 파일은 저장소에 넣지 않는다(63MB PDF). 여기 있는 것은 파이프라인이 소비할 **원천 데이터와 해시**뿐이며, `timeline.json`이나 페이지 매핑은 아직 아니다.

## 파일

| 파일 | 내용 | 크기 |
|---|---|---|
| `deck-inputs.json` | 원본 경로·SHA-256·페이지 수·SRT 오프셋·양쪽 덱의 PDF 책갈피 전체 | 8KB |
| `deck-pages-final-290.json` | 290쪽 덱의 페이지별 OCR 텍스트(1~290) | 291KB |
| `deck-pages-r17-clean-257.json` | 257쪽 덱의 슬라이드별 PPTX 텍스트(1~257) | 72KB |
| `srt/plaud1_1233-1733_5h.srt` | 전사본 1 (7,995 세그먼트, 12:33 시작) | 485KB |
| `srt/plaud2_1733-1813_40m.srt` | 전사본 2 (1,174 세그먼트, 17:33 시작) | 76KB |

## 출처와 한계

- `final-290` PDF `4b1affb4…`(290쪽)는 **이미지 기반**이라 텍스트 레이어가 사실상 없다(290쪽 전체 4,902자, `pdftotext`는 290바이트만 냈다). 그래서 페이지 텍스트는 100dpi 렌더 + macOS Vision `VNRecognizeTextRequest`(ko-KR/en-US, accurate, `usesLanguageCorrection=false`) OCR이다. **매핑 초안용이며 정본 텍스트가 아니다.** OCR 오류(예: `벨 1분위`, `서울연도벌인허가실적`)를 그대로 둔다.
- `r17-clean-257`은 PPTX 텍스트 프레임에서 뽑은 **정확한 텍스트**다. 같은 발표의 다른 계보다(290 ↔ 257 페이지 번호가 다르다).
- SRT 타임코드는 **각 파일 시작 기준**이다. `plaud-2`는 `offsetSeconds: 18000`(17:33 − 12:33)을 반드시 더해 이벤트 시작(12:33) 기준 초로 정규화한다.
- 두 덱 모두 PDF 책갈피에 강연 시작·끝 페이지가 있다(`deck-inputs.json`의 `bookmarks`). 14 프로그램(개회·강연 11·휴식 2·폐회) 중 덱이 다루는 것은 강연 11개와 프로그램 안내·후원·부록이다.
