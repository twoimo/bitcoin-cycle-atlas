# 독립 수치 검증기 갱신

검토일: 2026-10-26. 제품 런타임을 동결한 상태에서 검증기와 독립 계약 fixture만 수정했다. 금융상품·보상·유동성 구현을 검증기의 정답 함수로 다시 호출하지 않았다.

## 실패와 원인

수정 전 `node scripts/verify-system-numerics.mjs`를 실제 실행하면 `paths:cash-conservation: 0 != -51848.04928134568`로 실패했다. 해당 검사의 허용오차는 약 0.001289였다. 검증기는 상환 뒤에도 과거의 고정 연 금융비용을 계속 차감했으며, 전체 코인 자동 복리와 채무 감소 전액을 현금 상환으로 간주하는 이전 모형을 사용했다.

제품에는 이미 확인된 쿠폰의 결제·전환 후 중단, 전환주식과 원금 제거, 유동 ETH만의 비용 지급, 보상 수령과 출금 대기, 미지급 부채 보존이 적용되어 있었다. 검증기를 새 회계 명세에 맞게 고쳤으며 제품 수치나 기존 허용오차를 바꿔 통과시키지 않았다.

## 독립 계산 방법

- `tests/fixtures/treasury-contract-oracle-2026-10-26.json`에 문서에서 검토한 상품별 잔여 원금·쿠폰·풋·만기·전환주식 수를 별도로 보존했다. 재무 기준일이 달라지면 검증이 실패하여 새로운 계약 검토를 요구한다.
- 상품의 활성 일수와 해당 쿠폰을 곱해 구간 금융비용을 직접 합산한다. 현금 결제 원금과 전환으로 제거된 원금을 분리하고, 각 원장 전이는 한 번만 반영되는지 확인한다.
- 현금 보존식은 운영·금융비용, 현금 상환, 매각 순유입, 보통주 순유입과 미지급 부채의 증가·감소를 각각 합산한다. 전환된 원금을 현금 지출로 차감하지 않는다.
- ETH 보상은 직전 활성 스테이킹 원금과 고정 일별 환산율로 계산한다. 수령 주기는 **하루씩 열거**한다. 제품의 여러 수령일을 한 번에 처리하는 닫힌식과 다른 알고리즘으로 수령 전 보상과 유동량을 검증한다.
- 출금 요청·해제·슬래싱 노출·새 매입을 별도 대기열로 추적하여 유동·스테이킹·출금 대기·보상 풀의 각 잔액과 총량을 확인한다. 미지급금은 기타부채에 포함되어야 한다.
- 전환주식, 무상 희석, 유상 발행 후 주식 수와 기타자산 할인도 검산한다. 잔여가치 소진 이후에는 가격 0과 운영 잔고 동결을 확인한다.

공통 `near()`는 기존의 `absolute + 128 × Number.EPSILON × max(1, scale)` 공식을 그대로 사용한다. 기존 코인·현금 보존 검사의 절대항 `1e-7`도 유지했다.

## 실제 실행 결과

`node scripts/verify-system-numerics.mjs`가 통과했다. [전체 수치 receipt](system-numerics.json)에 제품·검증기·fixture 해시와 오차를 저장했다.

| 확인 범위 | 실제 건수 |
|---|---:|
| 계수한 수치·유한성 assertion | 318,010 |
| 실제 자료의 목표 연결 재무 경로 | 12 |
| 운영 상태 전이 | 1,483 |
| 흡수 상태 이후 동결 전이 | 101 |
| 독립 열거한 보상 수령 | 958 |
| 재무 경로의 전환 사건 | 9 |
| 조작한 출력에 대한 음성 대조 | 4 |

12개 경로는 MSTR의 세 자본 정책 × 세 경제 조건, BMNR의 기본 자본 정책 × 세 경제 조건이다. 음성 대조는 현금 $1 생성, 결제 후 쿠폰 비용 추가, 전환 후 원금 미제거, 가짜 보상 1 ETH를 각각 출력 복사본에 넣었다. 네 경우 모두 의도한 회계 assertion에서 실패했다. 제품 파일은 조작하지 않았다.

별도의 `verify-system-independent-review.mjs`는 재무 계산을 포함하지 않아 수정하지 않았다. [독립 검토 receipt](system-independent-review.json)의 달력 34,356사례, 결측 명시 불변성 80사례, 기간 비교 1,451사례, 관측 prefix 325사례, rolling prefix 10사례와 binary64 경계 검사가 통과했다.

## 전체 게이트의 추가 연결 오류

첫 전체 실행은 재무 검증기를 통과한 뒤 자산 비교 음성 대조의 `data:` 모듈 import에서 실패했다. `verify-asset-comparison.mjs`가 `cycle-engine.js?v=1.19.0` 문자열만 치환하고 현재 `?v=1.29.0` 상대 경로를 남겼기 때문이다. 실제 상대 import를 원본 engine URL 기준의 파일 URL로 해석하고 query string을 보존하도록 로더만 수정했다. 불변식·변이 표적·assertion은 바꾸지 않았다.

수정 후 **`npm run verify:numerics` 전체가 exit 0으로 통과**했다. [전체 실행 로그](verify-numerics.log)에 여섯 명령의 출력을 보존했다. 자산 비교의 독립 참조는 18자산·103,931종가·400연도 표본을 확인했고, 16개 변이는 모두 해당 불변식 assertion에서 거부되었다. 모듈 import 오류를 변이 탐지 성공으로 세지 않았다.

## 범위

이 검사는 현재 자료와 명시한 유한 정책·경로에서 회계와 계산의 일관성을 확인한다. `verify-treasury-paths.mjs`의 별도 53,016개 일별 상태 검사를 다시 실행하거나 그 결과를 이 검증기의 건수에 합산하지 않았다. 미래 시장 정확도, 실제 전환·풋 행사, 거래·출금 가능성, 계약상 법률적 구제 수단, 모든 부동소수점 입력에 대한 보편적 증명을 뜻하지 않는다. 로그에 출력된 단일 실행 시간은 성능 개선 비교로 사용하지 않는다.
