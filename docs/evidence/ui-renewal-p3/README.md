# R19 P3 — 대시보드 구현 후보

원격 제품 후보 **`042b04a4de56ece2bf5a6bd898b750ec5170e9f0`**. 검증한 로컬 후보는 **`a4f127f2552db288bba1483510cc57ce9be13784`**이며 두 커밋의 전체 Git 트리가 동일하다. 기준은 **`fbb46aac4e94e22953f3bcae1f572b74826954d0`**, 브랜치는 `fix/tradingview-responsive-20261110`이다. 릴레이·리서치·자산·공모주·시장의 카드 그리드와 알약 필터를 구현했다. **P3 수용은 네이티브 실측 대기**다. 원래 검사기는 Chromium 시작 단계에서 차단됐으며, 20개 화면의 오버플로 0이나 접근성 통과를 주장하지 않는다.

## 원격 커밋과 검증 후보의 대응

GitHub 연결 경로로 제품을 반영하면서 커밋 메타데이터가 새로 생성됐다. 원격 브랜치를 Git으로 다시 받아 확인한 결과, 검증 후보 `a4f127f2552db288bba1483510cc57ce9be13784`와 원격 제품 `042b04a4de56ece2bf5a6bd898b750ec5170e9f0`의 전체 트리는 모두 **`869e8da4088aab544fed54262778287093fe4dfa`**, 파일 차이는 **0**이다. 업로드한 제품 blob **20/20**도 로컬 Git blob ID와 일치했다.

원본 검증 영수증의 `sourceCommit`은 실제 실행한 로컬 후보를 유지한다. 원격 SHA로 원본을 덮어쓰거나 원격 후보에서 별도 실행했다고 기록하지 않는다. [publication.json](publication.json)에 두 커밋의 대응과 비교 결과를 남겼고, [tested-product-commit.txt](tested-product-commit.txt)는 로컬 검증 후보의 정확한 Git commit object 내용이다. 네이티브 미검증 상태는 두 후보에 동일하게 적용된다.

## 증거와 재현

원본 JSON/TAP/log는 `raw/`에 gzip으로 보관했다. [raw-manifest.json](raw-manifest.json)은 **37개 원본**과 압축본의 바이트 수·SHA-256을 기록한다. 압축을 풀었을 때 원본 바이트와 동일함을 확인했다. [manifest.json](manifest.json)은 최종 증거 파일의 해시 목록이다.

원래 P1 검사기는 다음 명령으로 7경로 × 4폭을 검사하며, 그 안에 P3의 20개 조합이 포함된다. `--out`은 아직 없는 새 디렉터리를 사용한다.

```sh
node scripts/verify-ui-renewal-p1-browser.mjs --out build/r19-p3-native-next/p1
```

집중 검사·typecheck·정적·CSS·preload·Pages 명령은 [checks.json](checks.json)에 argv 그대로 있다. 기존 ETH·반응형·축·A-9의 실제 argv와 환경은 `raw/native/execution.json.gz`, 반응형 서버 연결을 바로잡은 실행은 `raw/native-responsive-local/execution.json.gz`에 보존했다. 기존 실행의 임시 서버 주소를 새 측정에 재사용하지 않는다.

P3를 닫으려면 같은 후보에서 320·390·768·1440의 20화면, 가로 오버플로 0, 표 밀도와 기존 네이티브 게이트를 실제로 확인해야 한다. P2b·P4·P5, main push·배포는 수행하지 않았다.
