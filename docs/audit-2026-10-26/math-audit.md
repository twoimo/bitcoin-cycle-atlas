## 결과와 기준 소스

**ISSUES → 수정 후 집중 검증 PASS.** 감사 시작 시점의 기준은 `main` 커밋

검사 런타임은 Node `v24.22.1`이다. 실행 당시 소스 해시와 수치 근거는
[`math-results.json`](math-results.json)에 있다. 이 파일의 해시는 감사 당시
작업 소스의 신원이며, 뒤따르는 릴리스 import 버전 변경의 신원을 대신하지 않는다.

### 최종 제품 소스와의 대응 확인

최종 런타임 커밋은 `c8f9d985a7a99cdee13a5c74eeda37168f1c7ea8`이며,
그 부모 `65182efcb9a833b2be091c552a0291d47d50b32c`에는 동시에 진행된
자산 비교표 푸터 제거가 포함되어 있다. 원래 실행 기록의 해시·오차·검사
횟수는 보존하고, JSON의 `finalSourceReview`와 `finalSourceCorrespondence`에
최종 파일 신원과 이후 변경을 별도로 기록했다.

- `asset-comparison.js`, 자산 검증 스크립트, 신규 수학 회귀 검사 파일은
  이 하위 감사가 실행한 소스와 바이트가 같다.
- `detailed-forecast.js`는 `market-structure` import의 캐시 질의만
  `1.23.0 → 1.26.5`로 바뀌었다. 그 한 질의를 되돌린 파일의 SHA-256은
  원래 실행 소스와 정확히 같다.
- `market-structure.js`는 이후 `observations(input, asOf)`의 입력 검증을
  보강했다. `Array.filter`가 희소 배열의 빈 칸을 건너뛰던 문제를 인덱스
  순회로 고쳐 빈 칸·잘못된 튜플 길이·유효하지 않은 날짜·중복·역순 날짜를
  거부한다. cutoff 이후의 **가격값**은 과거 결과의 검증 의존성이 되지
  않지만, 날짜 구조·순서는 전체 입력에서 검증한다. 모든 미래 입력을
  무조건 무시한다는 의미가 아니다.

마지막 보강에서 바뀐 함수만 이전 내용으로 복원한 파일의 해시가 원래
독립 검토 소스 `1d6659b20343ae885a38c6bc5c0c057f1b439e4cbbc35552cdeadc4b20a294a3`
와 일치함을 확인했다. 최종 파일 해시는
`cc840a90b3c5bc83e86f27bf891108da04fdd0c5ce348478eadee3f96950383e`이다.
따라서 이동 계산 함수와 기존 oracle이 실행한 명시적 `asOf` 없는 경로의
내용은 동일하다. 이 대응 검토를 새 수치 sweep 실행으로 표기하지 않았고,
기존 oracle의 결과를 새 `asOf` 검증 분기의 검사 결과로 확대하지 않았다.
그 분기의 회귀 검사는 `tests/market-structure.test.mjs`의 두
`invalid future price` / `as-of scope` 검사에 있다.

## MATH-01 — 갱신된 자료에서 상세 전망의 기본 호출 실패

`dist/detailed-forecast.js`의 `context`는 명시적인 `asOf`가 없을 때
`referenceDate`를 `2026-10-22`에 고정했다. 저장된 BTC 원자료의 마지막
관측은 이미 `2026-10-23`이므로 다음 정상 호출이 실패했다.

```js
buildDetailedForecast(btcDaily, { sampleCount: 16 });
// RangeError: referenceDate must follow the latest completed UTC price
```

원인은 가격 모델이나 시뮬레이션 실패가 아닌, 관측 갱신과 기본 발행일의
불일치다. 기본 발행일이 마지막 완료 관측보다 앞서거나 같으면 관측 다음
UTC 날짜를 사용하도록 수정했다. 오래된 고정 자료의 기존 기본 발행일은
유지하며, 사용자가 명시한 잘못된 발행일은 계속 거부한다.

`tests/math-audit-20261026.test.mjs`는 고정 BTC fixture에 **검사용 합성
관측만** 추가하여 실패를 재현한다. 수정 후 기본 호출은 명시적
`referenceDate: '2026-10-24'` 호출과 전체 결과가 같다. 합성 관측을 시장
원자료에 저장하지 않았다. 현재 장기 전망 UI는 발행일을 명시하여 호출하므로
이 오류가 현재 장기 차트까지 중단시켰다고 주장하지 않는다.

## MATH-02 — 같은 수학적 경계를 다른 매도 단계로 분류

지난 다섯 해의 상승폭이 각각 `10%, 30%, 10%, 30%, 20%`이면 연도별
동일 가중 평균은 정확히 `20%`이다. 올해 첫 가격 `100`에서 `120`으로
오른 경우도 정확히 `20%`이다. 기존 연산에서 두 값은 서로 다르게 반올림됐다.

| 값 | 기존 계산 결과 |
|---|---:|
| 과거 평균 상승폭 | 20.000000000000004% |
| 올해 첫 가격 대비 변화 | 19.999999999999996% |
| 분류 | 분할 매도 |
| 정의한 경계에 따른 분류 | 적극 매도 |

`dist/asset-comparison.js`에서 변화율을 `(가격 − 기준가) / 기준가 × 100`으로
계산하여 `가격 / 기준가 − 1`의 불필요한 소거 오차를 줄였다. 분기 비교는
두 값의 크기에 대한 `8 × Number.EPSILON` 이내 차이만 경계의 동률로
처리한다. 가격이나 업무 기준을 소수 몇 자리로 반올림하지 않는다.

검사는 네 가지 가격 단위에서 네 경계의 정확한 동률 16개를 확인한다.
경계 가격의 양쪽 `±0.00000001` 차이는 세 단위에서 서로 구분하는
24개 경우도 확인한다. 현재 저장 자료의 **18개 판단 단계는 전후 동일**하다.
이 수정은 경계 계산의 일관성을 바로잡으며 과거 평균 경계의 투자 성과를
새로 입증하지 않는다.

검증 스크립트의 실제 비교문이 바뀌었으므로
`scripts/verify-asset-comparison.mjs`의 기존 포함 경계 mutation을 대응시켰다.
동률 허용을 삭제하는 결함과 허용 오차를 크게 넓히는 결함도 각각 추가했다.
두 변경 모두 의도한 공개 결과 검사에서 실패한다. 전체 **16/16** 결함
주입이 해당 불변조건으로 검출되고, 마지막 정상 소스 재실행도 통과한다.

## 독립적인 성능 패치 수학 검토

별도 담당자가 수정한 `market-structure.js`의 실제 `computeRollingStates`
결과를 독립적으로 비교했다. oracle은 매 창의 로그 평균과 표본 표준편차를
전체 재계산하며, 운영 코드의 이동 큐·보정합·두 스택 Welford 집계를
복제하지 않는다.

```sh
node docs/audit-2026-10-26/math-independent-check.mjs
```

| 국면의 가격 단위 불변성 | seed 834382, 200행 경로 80개 × 4개 배율 = 320개 전체 국면 벡터 일치 |
| 기하평균과 같은 가격의 분기 | `[1, 4, 2]`, `1e-300`부터 `1e300`까지 8개 배율에서 `pullback` 일치 |

이는 유한한 입력 집합의 검사다. 모든 이진 부동소수 입력에 관한 정리나
국면 분류의 경제적 유효성 증명이 아니다.

현금·코인·선순위 청구권·발행 주식 수의 회계식, MDD의 시간순 고점/저점
정의, 과거 자료만 사용하는 명시적 cutoff, 미래 경로의 조건부 표시는 코드와
기존 검사에서 확인했다. 이 감사는 모든 외부 공시의 최신성이나 모든
누락 변수를 다시 조사한 금융 리서치가 아니다. 미래 가격의 정확도, 조건
범위의 확률 보장, 매수·매도 단계의 수익성, 실제 조달 가능성은 증명되지
않는다. 그 한계를 완화하는 새 수치나 확률을 추가하지 않았다.
