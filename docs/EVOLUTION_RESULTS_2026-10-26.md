# 1~5단계 고도화 구현과 검증 결과

이 보고서는 v1.27.1에서 시작해 최신 main의 v1.28.2 기능과 갱신 자료를 보존한 v1.29 구현을 설명합니다. 구현, 계산 검산, 브라우저 측정, 형식 검증과 실제 배포 결과는 각각의 증거로 확인합니다. 마지막 공개 배포의 소스·명세는 사이트의 `publication.json`과 GitHub Actions의 공개 응답 확인 단계에 기록됩니다.

## 기존 차트 스타일로 비교표 통합

사용자의 추가 요청에 따라 비교표를 기존 트레이딩뷰 방식의 어두운 차트 작업 화면에 맞췄습니다. 별도 녹색 배경과 밝은 구분선, 자산군별 종목명 색상을 공통 배경·표면·문자·테두리 토큰으로 바꿨습니다. 제목과 툴바를 압축하고 숫자 폭을 고정했습니다. 종목명은 중립색이며 수익률과 판단 상태에 의미 색상을 사용합니다. 읽는 법·판단 근거·판단 이력도 같은 표면과 버튼 스타일을 사용합니다.

18개 자산, BTC 첫 행, 열의 의미, 종목명과 표 머리글 고정, 모바일 가로 이동 및 기존 판단 기록은 유지합니다. 320·390·768·1024·1440px의 실제 Chromium 검사에서 상단 버튼 겹침, 문서 가로 넘침, 고정 열 정렬, 표 안의 양축 스크롤과 이력 조작을 확인했습니다. 데스크톱 본문 행은 실제40px, 터치 화면은 실제53px입니다. 320px의 상단 아이콘은32×44px이며 모든 조작을44×44px로 검증했다고 표현하지 않습니다. [새 비교표 화면 증거](evolution-2026-10-26/ui/tradingview-theme/README.md)에 실제 치수와 캡처를 보존합니다.

## 발견한 실제 결함과 수정

### 재무 계산

지급에 쓸 수 있는 유동 ETH와 평가상 보유 자산을 분리했습니다. 출금이 끝나기 전에는 잠긴 자산을 매도할 수 없고, 부족액은 사라지지 않고 미지급 부채에 남습니다. 상환 또는 전환된 상품은 이후 쿠폰을 만들지 않으며, 주식 전환은 원금 청구권 제거와 발행 주식 증가를 함께 반영합니다. 풀의 합과 총보유량이 다르면 계산을 거부합니다.

비재스테이킹 보상은 매일 발생하는 현금성 보상입니다. 긴 구간 한 번 계산하면서 보상을 원금에 합성 복리로 넣던 부분을 고쳤습니다. 고정 일별 발생량과 실제 보상 수령 경계를 사용하여 여러 짧은 계산과 같은 총액이 됩니다. 이 정책은 재스테이킹을 가정하는 다른 경제 모형과 구별합니다.

전액 충당 가능한 매도에서도 나눗셈·곱셈의 반올림으로 작은 잔액이 남아 지급 부족으로 표시되던 오류를 수정했습니다. 지급 능력의 분기를 보존하며, 실제 아주 작은 부족액을 임의 허용오차로 지우지 않습니다. 과거 잘못 계산된 조기 부족 시점은 폐기했습니다. 2035년 UI 범위와 더 긴 조건부 경로의 부족 시점도 혼용하지 않습니다.

### 자료와 공개 신원

공급자별 실제 수집 시각 대신 전체 자료 묶음 생성 시각을 사용하던 연결을 바로잡았습니다. 완료 이전 관측·알려진 공개 시각 이후가 아닌 수집 등 순서 모순을 거부합니다. 공급자 공개 시각이 없으면 모르는 값으로 남깁니다.

공개 명세는 누락·추가 파일, 숨김 파일, 링크, 잘못된 경로, 다른 바이트와 명세 상태 불일치를 검사합니다. 검증된 후보가 같은 커밋·파일 내용으로 준비되어야 하며, 공개 응답도 그 신원과 같아야 확인 완료가 됩니다. 별도 배포 가드는 업로드·배포 직전에 현재 원격 main을 대조합니다. 원격 전체 파일의 원자적 배포나 모든 장애를 증명한 것은 아닙니다.

### 실제 조작과 검증 도구

기록 차트의 좁은 화면 날짜 눈금, 크기 변경 시 선택 날짜 손실, 네이티브 기간 선택의 키보드 포커스 손실, 주식 정보창을 닫자마자 차트로 이동할 때 늦게 온 close 이벤트가 포커스를 빼앗는 문제를 재현하고 수정했습니다.

형식 검증기가 예상 반례 문구를 출력한 뒤 비정상 종료한 프로세스를 성공적인 실패 대조로 받아들이던 오류도 고쳤습니다. 실제 TLC를 실행한 래퍼를 SIGKILL로 종료시켜 이전의 잘못된 PASS를 재현했습니다. 현재는 정상 종료 여부와 정확한 종료 코드를 먼저 요구합니다. 새로운 코드 때문에 맞지 않게 된 임시 테스트 의존성과 변이 선택자는 같은 보호를 제거하도록 갱신했으며, 불변식이나 필요한 테스트 수를 낮추지 않았습니다.

## 성능 측정

성능 통합 소스 `7261c18`의 동결 복사본과 원래 기준판 `3530033`을 비교했습니다. 같은 BTC·18자산 원자료, Chromium156, 390×844 터치 에뮬레이션, CPU4배 제한, 로컬 무압축 서버, 같은 한국어 글꼴에서 전후 각각 5회 교대로 실행했습니다. 총20회에서 페이지 오류와 누락 자원이 없었습니다. 이 수치는 이후 추가된 비교표 CSS 테마와 PR37·자료 갱신 이전의 측정입니다. 최신 화면의 레이아웃·기능 검증과 구별하며 새 CSS의 추가 속도 향상으로 주장하지 않습니다.

독립형 HTML은 전체 연구·판단 기록·예측 경로를 포함해 약18.1MB입니다. 온라인 화면은 선택할 때 필요한 기록을 읽지만 오프라인 파일은 전체 바이트를 포함하는 선택입니다. 모든 산출물의 크기가 줄었다고 주장하지 않습니다. 그대로 매일 보존하면 커지는 원장 비용은 기본30개 새 완료 관측 간격과 명시적인 예외로 제한하며, 기존 기록을 삭제하거나 정밀도를 낮추지 않습니다.

## 검증 근거와 범위

- PR37·최신 자료와 새 비교표 테마 통합 후 전체 회귀 **1,189개 통과**, 실패·취소·건너뜀·TODO 0. 원자료·연구 자료·ETH 사건·주기 산출물·정적 경로·차트 작업량·예측 원장 검사도 별도 통과했습니다. [마지막 통합 검사 기록](evolution-2026-10-26/final-integration/README.md)에 명령과 원시 출력을 보존합니다.
- 독립 수치 게이트는 **318,010개 계수 검사**, 실제 자료12개 재무 경로, 의도한 회계 오류4개와 자산 비교 오류16개 거부를 포함해 통과했습니다. [독립 회계 검산](evolution-2026-10-26/numerical-oracle-review.md)은 기존 허용오차를 유지하고 제품의 닫힌식과 다른 일별 열거 방식으로 보상을 대조합니다. 이 건수는 별도53,016개 일별 상태 검사를 합친 숫자가 아닙니다.
- 형식 검증 **27개 TLC 실행**: 정상/속성 실행8개가 종료0, 의도한 불변식 위반19개가 종료12. 실제 코드 보호21개를 제거했을 때 대응 assertion이 종료1로 실패하고, 원래 임시 복사본은 복구 후 통과합니다.
- 정상 유한 모델의 서로 다른 상태 수: 시장 소유권2,081·재시도15, 주식46,252, ETH2,243, 공개20. 각각의 경계와 대응 함수는 [독립 검토](evolution-2026-10-26/publication-independent-review.md)에 있습니다. 새 경제 모형 전체가 이 유한 모델의 증명 범위에 들어가는 것은 아닙니다.
- 기록 화면의 실제57개 점검 그룹은 데스크톱·320px폰·태블릿·축소 레이아웃/고밀도 reflow proxy·실제 file 오프라인을 포함합니다. [화면 증거](evolution-2026-10-26/ui/README.md)에는 해당 실행의 정확한 바이트와 입력, 합성 테스트 응답의 범위가 남습니다. 실물 기기·Safari·브라우저 UI의 실제200% 확대·전체 WCAG 인증을 주장하지 않습니다.
- 정상 공개는 전체 로컬 산출물을 검산한 뒤, 공개 명세 신원과 핵심 HTTP 파일4개를 추가 대조합니다. 같은 태그의 릴리스 재실행은 최초 명세를 보존하고 동일 바이트만 허용합니다. 실제 Actions·릴리스 결과는 저장소의 실행 기록에서 별도 확인합니다.

## 남아 있는 경험적 한계

새 원장의 전향 예측 점수는 아직 없습니다. 30·90·180일 목표에 실제 관측이 쌓여야 평가할 수 있으며, 늦게 생성한 계산을 과거에 공개한 예측으로 바꾸지 않습니다. 주기·시나리오 음영은 확률구간이 아닙니다. 기록 사이의 정확한 로그 차이를 원인·인과관계로 해석하지 않습니다.

금융상품·우선주·스테이킹의 확인되지 않은 조건을 사실처럼 추정하지 않습니다. MSTR 전환기간의 보수적인 모형 제한, 미분해 비용, BMNR 초기 잠금 비율·출금 및 보상 지연은 [회계 문서](TREASURY_INSTRUMENT_LIQUIDITY.md)와 화면에서 명시합니다. 기본 원자료의 기업별 기준일·가격 정의가 다르므로 최신 NAV 또는 검증된 거래 전략으로 표시하지 않습니다.

작업은 pstack의 분담·실패 재현·측정·도메인 모델·검증 스킬 생성/유지·상태전이도·결정 기록 절차를 적용했습니다. 서로 분리한 담당과 독립 검토를 사용했으며, 실행하지 않은 타사 세 모델 검토를 완료한 것으로 표시하지 않습니다.

## 원본 소스와 공개 전달

생성·측정 당시 로컬 Git 객체는 [검증한 원본 bundle](evolution-2026-10-26/SOURCE_PROVENANCE.md)로 보존했습니다. 연결된 GitHub API가 만드는 공개 커밋과 원래 생성 커밋을 혼동하지 않습니다. 원장의 원래5개 기록과 모든 입력·출력 해시는 그대로이며, 공개 파일 트리의 동일성은 별도로 대조합니다.
