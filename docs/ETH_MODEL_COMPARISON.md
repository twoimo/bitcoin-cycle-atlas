## 현재 결정

BTC 사이클을 ETH에서 배제하지 않는다. BTC에서 실제 사용 중인 기준선을 전이한 경우와 ETH 관측으로 같은 로그 앵커 구조를 재추정한 경우를 기존 ETH 예시 및 경제 입력 후보와 비교한다. **새 후보는 기본값으로 승격하지 않는다.** 이번 구현은 별도 브랜치의 비교·검증 코드이며, 경제 자료가 부족한 후보를 값이 있는 모형처럼 표시하지 않는다.

기준 소스는 main 커밋 30805dacdcf0aa3ea991439de87d5f9a38c59f25, 트리 58f20c1ac5ee3f40ac4971a5eaa7e21577f70957이다. 기존 v1.29.0과 PR #38은 이미 병합·배포되었다. 기존 PR #12, 판단 이력 저장 잠금, 비교표, immutable forecast ledger를 덮어쓰지 않는다.

이 문서는 ChatGPT의 소스 근거 논제와 구현 계약이다. 실제 Gemini 소스 반대 검토 및 그 보고서에 대한 ChatGPT 역검증은 **미완료**다. GitHub 앱만 사용하는 현재 작업에서 Gemini 호출 기능을 이용할 수 없고 이전의 제한적 검토 생략 승인은 이 변경에 적용하지 않는다. GitHub CI 성공을 외부 모델 검토나 금융 예측력 검증으로 해석하지 않는다.

## 실제 읽은 기존 수식

dist/detailed-forecast.js의 BTC 기본 조건은 다음과 같다.

- 고점에서 12개월 뒤 저점, 고점에서 48개월 뒤 다음 고점. 기본 고점권 진입 3개월 선행 및 3개월 체류. 이 값은 경험적으로 재추정한 ETH 법칙이 아니다.
- 다음 고점의 가격 기준: \(Q_{k+1}=Q_k(Q_k/Q_{k-1})^{0.75}\).
- 다음 저점의 가격 기준: \(L_{k+1}=Q_{k+1}(1-0.50)\).
- 두 앵커 사이: \(\log B_t=(1-u)\log A_0+u\log A_1\).
- 기존 무작위 예시는 로그 잔차를 더하고 최종 bridge 잔차를 차감한다. 기준선의 산식과 무작위 굴곡은 별개다.
- BTC 장기 엔진은 이러한 근거리 사이클 변위를 감쇠시킨다. 무한히 48개월 파형을 반복하지 않는다.

## 비교 후보와 경제적 연결

| ID | 가격에 연결되는 계산 | 추정·가정의 구분 |
| --- | --- | --- |
| flat | \(P_{t+h}=P_t\) | 변화 없음 기준선 |
| shrunkenTrend | 최근 180일 로그 추세를 0.25배로 축소하고 기존 보수적 추세 규칙을 적용 | 기존 고정 규칙 |
| btcLinked | \(\log(P^{ETH}_{t+h}/P^{ETH}_t)=\hat\beta_t h\hat\mu^{BTC}_t\) | beta는 과거 365일 정렬 수익률에서 추정. 미래 BTC는 과거 보수적 추세로 예측 |
| btcTransfer | \(P^{ETH}_t B^{BTC}_{t+h}/P^{BTC}_t\) | 실제 BTC 상세 사이클 기준선·타이밍을 사용. 장기 외부 가치평가 및 무작위 잔차는 제외하며 BTC 달러 목표가를 ETH에 복사하지 않음 |

| legacyEth | 기존 ETH base의 고정 seed 단일 예시 | seed 선택 실험 없음. 세 조건 폭은 별도 시나리오 진단 |
| economic | 공개·수집 시각이 적격인 경제 변수의 직접 기간별 ridge 로그 수익률 추정 | 표준화·회귀는 학습 부분만 사용. 계수는 연관성이며 인과 가치평가로 주장하지 않음 |
| combined | \(\log P=(1-w)\log P_{cycle}+w\log P_{econ}\) | 이전에 결과가 확정된 비중복 공통 표본으로만 w 추정. 경제 후보 부재 시 사용 불가 |

ETH 전환점은 하락·반등이 관측되어 확인된 뒤에만 추정에 참여한다. 과거 국면의 극값 날짜와 그것을 알게 된 확인 날짜를 구별한다. 관측으로 얻은 큰 반전 구간을 각각 독립적인 4년 시장 사이클로 세지 않는다. 향후 필수 앵커가 이미 지나갔거나 충분한 진폭 표본이 없으면 새로운 주기를 임의로 만들어 연장하지 않는다.

ETH/USD 예측과 ETH/BTC 상대강도 예측은 다른 타깃이다. 경제 모듈은 상대가격의 과거 변화만 설명변수로 이용하고 미래 ETH/BTC나 실현 미래 BTC를 입력하지 않는다. 접근성 확대에 ETH의 낮은 개당 가격이 필수라고 가정하지 않는다.

## 경제 자료 계약

코드의 metric catalog와 schema가 기계적으로 검사하는 계약이다. 최소한 관측 종료 시각, 측정 기간, 실제 공개 시각, 수집 시각, 자료 판본과 출처가 필요하다. 오래된 관측을 지금 수집한 것만으로 과거 예측 시점에 보유했던 자료로 인정하지 않는다.

- L1 사용량, L2 활동, blob 수요는 각각 구분한다. 활동량의 증가를 가격 증가 계수 1로 직접 대응시키지 않는다.
- 실행 수수료와 blob 수수료는 분리한다. L2 사용자 총 지출을 L1 수입에 더하지 않는다.
- EIP-1559 실행 base fee와 blob fee의 소각을 분리한다. priority fee는 이전이며 같은 소각으로 세지 않는다.
- 순 공급 변화는 consensus 순 발행과 별도로 확인한 전환 전 PoW block·ommer 발행을 더한 뒤 실행·blob 소각을 뺀다. 완전히 Merge 이후인 28일 창의 PoW 발행은 근거가 확인된 0이며 누락값을 0으로 채우지 않는다. 입금·출금·재스테이킹은 발행이 아니다.
- 스테이킹 잔고·대기 잔고와 별개로, 고정된 관측 집단의 실제 보상·벌점·priority fee·중복 제거 MEV에서 관측된 서비스·운영 비용을 뺀 28일 순수익률을 추정 입력에 넣는다. 회사의 ETH 유동성 원장을 네트워크 전체 스테이킹 데이터로 오인하지 않는다.
- 완료된 출금의 요청→실행 잔고 이용 가능 시간 중앙값을 대기 잔고와 별도 입력으로 사용한다. 완료 사례의 선택 편향이 있고 현재 대기열의 해소시간 예측은 아니다.
- 네이티브/래핑 ETH 담보와 스테이킹 청구권의 기초 ETH 담보를 중복 제거한 합을 공급 대비 비율로 입력한다. 보관된 기초자산과 여러 차례 발행된 영수증 토큰을 더하지 않는다.
- LST의 실제 거래 가능 유동성을 잔고나 backing 비율로 추정하지 않는다. 시각·거래 크기·시장 깊이·상환 조건을 갖춘 별도 고정 바스켓 자료가 필요하다.
- ETH/BTC 설명변수는 타깃보다 앞선 시각으로 제한한다.
- 경제 입력 v3는 13개 변환 특징과 ridge alpha 1을 사용하며, 기간별 최소 16개의 확정 비중복 학습 타깃을 요구한다. 이는 설계상 최소 문턱일 뿐 충분한 독립 시장 국면의 증거가 아니다. 규제 강도 및 감지·표본 최소값과 관측으로 추정한 계수를 구분한다.
- 변수별 로그 수익률 기여, 국소 민감도, 한 변수 제거 후 재추정 예측을 반환한다. 제거 결과가 있다는 사실만으로 표본 외 성능 기여가 증명되지는 않는다.

현재 저장소에는 이 계약을 충족하는 네트워크 경제 입력의 과거 판본 묶음이 없다. 경제 후보의 실제 과거 평가와 결합형은 사용 불가로 보고한다. 테스트에 쓰는 합성 자료는 계산·차단 규칙 검증 전용이며 실제 시장 자료가 아니다.

## 공유 ETH 경로와 시간

기존 ETH 화면과 BMNR은 buildEthereumAssetScenarioPaths를 공유한다. 이번 입력 경계 수정은 유효한 같은 기준일·seed 입력의 결과를 보존하면서, 직접 호출 시 기준일 이후 자료가 들어오는 경로를 차단한다.

UTC 코인 일말은 다음 날 00:00 UTC에 완료된다. 뉴욕 주식 종가와 같은 날짜라는 이유로 동시에 알 수 있던 가격으로 간주하면 안 된다. 신규 경제 입력은 실제 시각을 요구한다. 비교기에 실제 issuedAtByOrigin을 전달할 수 있으며, 없으면 다음 UTC 자정을 보수적 정보 한도로 사용한다. 모르는 과거 발행시각이나 공개시각을 만들지 않는다. **기존 date-only BMNR 발행 경계의 별도 정밀 시각 정산은 아직 이번 후보의 완료 근거가 아니다.** 이 문제를 확인하지 않고 새 후보를 BMNR 운영 입력으로 승격하지 않는다.

## 검증과 공개 조건

PR의 일반 CI가 기존 전체 테스트·수치·형식·정적·원장 검사를 수행한다. 추가 PR 전용 evidence workflow가 후보 테스트와 실제 저장 자료 비교를 실행해 완전한 JSON을 아티팩트로 보존한다. 실제 결과 수와 commit/run URL은 실행 후 결과 문서에서 확인한다. 작성된 테스트의 존재를 실행 성공으로 기록하지 않는다.

기존 비교표의 18자산·BTC 첫 행·다크 테마·320px/태블릿 시작·중간·끝 고정 열 정렬은 v1.29.0에 보존된 범위다. 비교표의 UI/CSS는 유지한다. ETH 차트에는 기존 deterministic baselinePrice를 파란 점선으로, 기존 단일 잔차 경로를 금색 점선으로 분리해 표시한다. 범례·선택 정보는 조건 기준선, 무작위 예시 1개, 세 조건 음영을 구분하며 적합된 경제 모형이나 확률구간으로 부르지 않는다. 이 표시는 가격 산식·seed·ETH/BMNR 공유 경로를 바꾸지 않는다. 새로운 브라우저 검증 결과가 있을 때만 새 실행으로 표시한다.

## ETH 표시 구분과 상태 검증 범위

별도 baselinePrice 선은 ETHUSD + crypto-conditional-daily 경로에 한정한다. 자동 축 범위는 음영이 꺼져 있어도 기준선을 포함하며, 화면 경계의 보간값은 실제 새 예측 관측으로 세지 않는다. 다른 자산 모형의 경로·자동 축에는 이 표시를 적용하지 않는다.

eth-view.js 변경은 범례·근거 문구·readout 종류 표시 및 두 줄 범례를 위한 headerInset에 한정한다. 비동기 상태, 요청 소유권, pagehide/pageshow, readiness 및 navigation guard는 변경하지 않는다. 기존 verify-eth-state의 17개 전체 initializer replay와 9개 실제 소스 mutation은 일반 CI에서 다시 실행하며, 모형 가격·렌더링은 별도 단위 및 실제 Chrome 검사로 확인한다. 상태 전이 모델의 행동·가드·매핑이 바뀌었다고 주장하지 않는다.
