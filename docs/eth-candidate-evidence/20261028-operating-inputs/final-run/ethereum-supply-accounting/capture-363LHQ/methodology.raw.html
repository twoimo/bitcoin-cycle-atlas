Methodology

How ETH supply is calculated.

The homepage is a live per-slot ledger. It starts from an audited supply and applies every supply-changing event through the latest fully accounted slot. Historical proofs check that running total against Ethereum state.

01

The live calculation

next supply =
  previous supply
+ issuance
− execution fee burn
− consensus penalties
− ETH destroyed by SELFDESTRUCT

Each slot is calculated incrementally; the account tree is reserved for historical audits. Deposits and withdrawals preserve total supply while moving ETH between execution and consensus.

In the live JSON, supply.checkpoint is the audited starting balance and supply.asOf is the newer slot reached by the live ledger. “Checkpoint” names the audit baseline; the ledger updates each slot.

02

How an audit baseline is assembled

Execution balance proof

full-state execution anchor
+ later PoW issuance and withdrawals
− base-fee and blob-fee burn
− proven SELFDESTRUCT destruction
= execution balance at target

The anchor fixes one complete execution state. Canonical supply-changing flows and exact balance changes carry it to a newer checkpoint.

State reconciliation

execution balances
+ all consensus balances
− deposits represented on both layers

Execution balances are rooted in a complete account-state sum and carried forward through exact canonical changes. All consensus balances means validator balances plus balances temporarily held in consensus queues. The deposit history identifies the amount represented on both layers.

Why block 15,082,718 appears in the proof

Coverage begins at genesis. At block 15,082,718, an independent enumeration of all 176,496,428 execution accounts produced 118,908,973.575220938641041929 ETH at that block's state root. This full-state cross-check sits within genesis-to-present coverage.

Creates ETH

Genesis allocation, historical PoW rewards, Beacon rewards.

Destroys ETH

Base fees, blob fees, consensus penalties, and rare ETH destruction caused by SELFDESTRUCT.

Preserves ETH supply

Transfers, deposits, withdrawals, and ETH held in an account.

03

Independent validations

Each validation compares the same quantity through independent data paths.

Historical flows vs full execution state

Side A: canonical genesis allocation and every PoW reward, adjusted by every fee burn and proven historical destruction through block 15,082,718.

Side B: an independent enumeration and sum of all 176,496,428 execution accounts at that block's state root.

Cadence: one full-state validation at block 15,082,718, followed by exact per-slot flow roll-forward.

Result: both produce 118,908,973.575220938641041929 ETH; difference 0 wei.

Scope: this project ran both the state-enumeration and genesis-flow paths.

Protocol flows vs execution-balance changes

Side A: withdrawals and fee burn recomputed from canonical block fields.

Side B: the net balance change across every account touched by the block.

Third check: fork-aware traces and exact pre/post balances classify genuine SELFDESTRUCT destruction.

Cadence: Side A and Side B run for every canonical execution block. Trace and pre/post-state classification runs in explicit proof batches.

Result: every completed block closes to 0 wei or carries hash-bound classified destruction.

Scope: distinct Erigon data paths provide both views on one node; live warnings queue intervals for proof classification.

Execution deposits vs Beacon state

Side A: every execution-layer deposit event replayed in order, including independent BLS validation of first deposits.

Side B: Beacon validator balances, pending balances, and deposit index at the paired state root.

Third check: the fresh state-derived supply must equal the accumulated per-slot ledger from the previous checkpoint.

Cadence: once every 7 days. The scheduled run starts Saturday at 03:15 in the Europe/Rome timezone; host recovery triggers catch-up.

Latest completed run: Loading…

Result: every deposit is classified as accepted, pending, applied, or protocol-excluded; the categories reconcile with a 0-wei state-versus-ledger difference.

Scope: project-operated Erigon and Prysm provide separate execution and consensus views.
