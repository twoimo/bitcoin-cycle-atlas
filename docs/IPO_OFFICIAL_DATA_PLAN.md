# 공모주 공식 자료 조사와 갱신 후보 설계

관측일: 2026-11-01 KST. 초기 조사 기준: `851a8c80137e9433d80666df14da70f522ee1028`. 현재 오프라인 후보의 기준 main: `6ab115c184e675e28bd236ebdb350a3c5685c34a`.

이 문서는 조사 결과와 검증 후보를 구분한다. 예정 IPO 전체의 완전성, 실시간성, 자동 공개 반영을 아직 보증하지 않는다. 기존 38 수집본 33건을 공식 확인 자료로 소급해 표시하지 않는다.

**현재 상태: HTML live 수집 중단, 오프라인 검증만 가능.** 후속 점검에서 [DART robots.txt](https://dart.fss.or.kr/robots.txt)의 `User-agent: *` 아래 `/dsaf001/main.do`, `/report/viewer.do` 등의 `Disallow`를 확인했다. 이 경로를 반복 조회하는 자동 수집은 채택하지 않는다. 기본 CLI는 HTTP 요청 전에 `blocked_source_policy`를 기록한다. 명시적 모의 transport를 주입한 오프라인 fixture만 실행한다. Actions는 수동 오프라인 점검이며 `schedule`이 없다. 기존 15분 HTML 수집안은 폐기했다. 문서화 API, 기존의 유효한 인증키, 실제 응답·이용조건 검증이 다음 단계이며 새 키·계정을 만들지 않는다.

## 목적과 완료 기준

- 공모주 화면의 상단·반복 설명을 줄이고 검색·필터·월별 스크롤·날짜 상세·접근성은 유지한다.
- 공식 신고서의 IPO 여부, 최신 정정·발행조건 확정·철회, 일반청약 날짜를 확인한다. 기존 상장사 유상증자·투자계약증권·일정 미정 관심 기업을 확정 IPO와 혼합하지 않는다.
- 수집 범위, 전체 건수, 모든 페이지 수신, 자료 관측 시각, 원문 접수번호와 SHA-256, 누락·충돌·미확인을 남긴다.
- 변경 후보는 기존 일정과 비교하되 조회 누락을 철회·취소·삭제로 추정하지 않는다. 부분 수집 실패는 성공한 빈 달력으로 바꾸지 않는다.
- GitHub Actions는 예약 실행 지연·누락 가능성이 있는 주기 확인이다. 푸시형 실시간 서비스라고 부르지 않는다.
- 공개 데이터 교체 전에는 실제 수집·필드 대조, 정상/실패/부분 응답 테스트, 기존 전체 회귀·정적 검사, 코드/자료 판본과 발행 manifest, 모바일/공개 화면 수락을 각각 확인한다.

공개 활용마당의 검색·엑셀 다운로드는 로그인·키 없이 실제 수락되었다. 2026-05-01~11-01 일반사항 검색에는 총 82건이 표시되었고, `ScritsDclrt.xls` 파일 다운로드를 확인했다. 이는 공개 화면용 경로의 실제 동작 증거이며 문서화 API의 인증·호출 성공을 의미하지 않는다. 화면 내부 읽기 경로는 안정성 보장이 있는 공개 API로 표현하지 않는다. 필드 일부를 추출한 요약은 정확성·완전성을 보장하지 않으므로 원문과 함께 확인한다. 이 문서는 별도 법률 판단이나 영구적 이용허락 증명서가 아니다.

청약달력과 공모게시판은 IPO 전용 목록이 아니다. 실제로 기존 상장사의 발행과 투자계약증권도 노출된다. `corp_cls=E`, 회사명, 보통주, 일반공모라는 말만으로 IPO를 분류하지 않는다. 원문의 `지분증권 등 상장을 위한 공모여부`와 `코스닥시장 신규상장` 등 명시적인 구분을 확인하고, 판정 불가 자료는 검토 대상으로 남긴다.

멜콘에서 DART 확정 신고서와 대표주관사의 청약 안내를 대조한 것은 개별 표본 검증이다. 모든 회사의 주관사 공고를 수집·검증했다는 의미가 아니다. 초기 조사에서 신규상장 구분 표를 DART viewer에서 직접 확인했다고 보고한 부분은 후속 조사에서 재현되지 않아 **inconclusive로 정정**했다. 부모가 대표주관사 PDF 전체 600쪽을 텍스트 추출해 다시 검색했다. 실제 구분 표는 **PDF 133쪽**에 `인수(주선) 여부 / 지분증권 등 상장을 위한 공모여부 / 인수 / 예 / 코스닥시장 신규상장`으로 있었고, PDF 136쪽(본문 표기 134쪽)에는 `본 주식은 코스닥시장 상장을 목적으로 모집하는 것으로`라는 설명이 있었다. 초기의 본문 135쪽 인용은 이 표의 정확한 위치가 아니었다. ## 결정과 작업 순서

### ADR-IPO-01: 기존 발행 계약을 유지한다

별도 raw-GitHub 데이터 브랜치나 출처를 검증하지 않는 외부 feed를 추가하지 않는다. 향후 공개 승격 시 기존 `refresh-data.yml`의 정확한 main 기준점·최소 allowlist 커밋·회귀 검사·publication manifest·같은 artifact 배포·공개 readback 방식을 재사용한다. 기존 crypto/equity 갱신·루틴·리플레이는 변경하지 않는다.

### ADR-IPO-02: 수집 후보와 공개 승격을 분리한다

초기 1회 표본 실행에서는 공개 화면으로 후보·커버리지·철회·충돌을 조사했다. 이후 robots 차단 경로를 확인해 live HTML adapter를 중단했다. 현재 기본 경로는 정책 차단 기록과 오프라인 검증만 수행하며 공개 `dist/data/ipo-calendar.json`은 교체하지 않는다. Actions는 `contents: read`의 수동 오프라인 점검이고 반복 트리거가 없다. API adapter와 실제 API 인증·원문 판별은 아직 구현·검증되지 않았다. 출처 실패·누락·미확인 IPO를 기존 공식 확인 상태로 승격하지 않는다.

### ADR-IPO-03: 출처와 신원을 필드별로 보존한다

가능하면 법인 고유번호와 접수번호를 신원으로 삼고, 다른 스팩·유사 이름·이전 상호를 이름 정규화만으로 합치지 않는다. 일정의 시작/종료/단일 날짜, 확정/희망 공모가, 주관사, 납입·환불·상장·IR·신고서제출은 각각 직접 확인된 값만 기록한다. 원문에서 구분되지 않은 값은 `null`/`needs_review`이며 추정 날짜를 생성하지 않는다.

### ADR-IPO-04: 완전성은 분모가 있는 수집 범위에만 쓴다

사이트가 수락한 전체 필터·기간·총건수·페이지 수를 남기고, 실제 받은 고유 행과 비교한다. 페이지 일부 실패·총건수 변동·중복·예상 구조 누락은 완전 수집이 아니다. 모든 시장의 모든 미래 IPO를 관측했다는 무제한 주장은 하지 않는다. 미공고 기업은 관심 목록으로 분리한다.

### WO-IPO-01~05

1. 상단 압축과 모바일/키보드/달력 회귀 검증.
2. 실제 관측 인터페이스에 묶인 후보 수집기, 출처 해시·전수 페이지·철회·IPO 구분·충돌 테스트.
3. read-only 수동 Actions에서 오프라인 경계·정책 차단을 확인한다. 현재 live HTML 수집·예약·공개 갱신은 없다. API adapter는 기존 인증키와 실제 응답 계약을 확보한 후 별도 구현한다.
4. 외부 교차 감사의 원문/소스 readback 및 material finding 처리. 후속 공개 승격은 검증 상태에 따른다.
5. 전체 회귀·정적·공개 발행 검증 후 공식 데이터·새 일정 단계·열린 화면 자동 반영을 연결하고, 세션 전체 잔여 작업을 마지막에 재정리.

## 위험과 수락 조건

- R-IPO-01: 오래된 요약·정정/철회 누락. 최신 접수번호·원문 확인, 철회 상태 보존, 충돌 격리.
- R-IPO-02: 페이지 누락·빈 응답·구조 변경. 총건수/페이지/고유 행 검증과 실패 시 이전 공개본 보존.
- R-IPO-03: IPO/유상증자 오분류·이름 충돌. 명시적인 신규상장 증거와 고유 신원; 불명확하면 검토 대기.
- R-IPO-04: 날짜 이월·역전·가짜 환불일. 실제 날짜 왕복 검사, 범위 순서 검사, 필드별 직접 출처.
- R-IPO-05: 동시 main 변경·오래된 artifact 배포. 기존 publication 계약과 비강제 push·배포 전 source 재확인.
- R-IPO-06: 과장된 실시간/완전성/교차 검증 표현. 실제 체크 시각·범위·분모·같은 원천의 파생 경로 여부 표시.

## 외부 감사 상태

현재 실제 ChatGPT thesis → Gemini 반대검토 → ChatGPT 역검증은 수행되지 않았다. 공유 coordinator 관측에서 ChatGPT FIFO의 다음 소유자는 별도 작업이었고, Gemini에는 타 소유자의 `uncertain` 작업이 남아 있었다. 이를 오래됐다는 이유로 해제하거나 계정·모델·슬롯을 바꾸지 않는다. 적용되는 공유 규칙은 `Outside urgency use FIFO and one active review per service`이다.

상단의 통상적인 UI 정리는 별도 검증 가능한 변경이다. 새 수집기는 가역적인 검증 후보로 유지하며, 이 문서를 실제 외부 감사의 완료 보고서나 공개 자동갱신 완료 증거로 부르지 않는다. 다음 단계는 고정된 후보 소스·질문·해시를 준비해 공유 admission에 등록하고, 실제 허용된 모드·계정에서 세 단계를 재개하거나 사용자가 이 작업의 검토 범위를 명시적으로 변경하는 것이다.


## 실행 증거와 현재 판본의 한계

- UI PR #54는 `56ccce18f58b9f233d84f58a51e49f6714cadbcb`에서 원격 verify·audit·GitGuardian을 통과했고 `6ab115c184e675e28bd236ebdb350a3c5685c34a`로 병합됐다. 해당 커밋의 Deploy Pages도 성공했다. 확장 evaluate의 실패 3건은 이전 실행과 화면·크기·오류 본문이 모두 같았다. 별도 리플레이 작업은 섞지 않았다.
- 정책 점검 이전 HTML prototype의 전체 현행 조회에서 게시판 3/3페이지·37/37 고유 행, OpenDART 6/6페이지·82/82 고유 행, 현행 지분 공모 원문 33/33건을 읽었다. 그 판본에서 23건이 신규상장 표·원문 청약일·게시판·달력과 일치했다. 나머지에는 IPO가 아닌 공모와 필드 해석 보류가 섞여 있다. 전 시장의 모든 IPO가 확정됐다는 뜻이 아니며 `verified`와 `marketComplete`는 false다.
- 전체 실행 뒤 연도 생략 날짜와 최신 관련문서 선택을 추가 보완했다. robots 확인 뒤 추가 live 조회를 중단했으므로 **마지막 보완 판본의 실제 33건 재실행은 하지 않았다.** 초기 전체 실행의 구현 해시는 실행 시점에 별도로 고정하지 못했다. 결과·출처 URL·응답 SHA를 현재 코드의 live 통과 증거로 소급하지 않는다.
- 현재 오프라인 테스트는 실제 표 셀, 음성 값 옆의 다른 문구, 철회 후 옛 일정 복원, 명시적 공시 계보, 같은 날 복수 보고서 순서 미확정, 중복 행·페이지 누락, 원문/달력 충돌, 한국 날짜·월/연 이월, 가격 불확실성 분리, origin/redirect 제한, 기본 live 경로의 무요청 차단, 출력 심볼릭 링크 보호를 검증한다. mock은 실제 API 인증 성공의 대체물이 아니다.
- `offer.price.priceText`는 신고서의 모집(매출)가액 원문 값이다. 최초 신고서의 희망 최저가일 수 있다. 일정 검증이 가격 확정 검증을 뜻하지 않으며 가격과 날짜의 불확실성을 분리한다. 납입일을 환불일로 만들지 않는다.
- 이름만으로 공시를 합치지 않는다. 실제 `family` control의 접수번호만 계보로 취급하고 현행 게시판의 유일한 최신 일자를 선택한다. 같은 날 복수의 권위 있는 게시판 행은 접수번호 크기로 확정하지 않는다. 옛 요약은 이력으로 남기며 최신 원문/게시판의 불일치를 덮지 않는다.
- 현재 공개 38 표와 공식 후보는 같지 않다. 예를 들어 공개 표의 `다비오` 청약은 11/10~11로 남아 있고, 조사한 DART 동명 신고서 `20261030000682`는 12/1~12/2였다. 법인·출처 연결과 변경 검토가 필요한 차이다. 후보를 자동 병합하거나 기존 표를 공식 최신 자료라고 표시하지 않았다.
- 공식 3단계 외부 감사는 모두 NOT_RUN이다. 별도 Astra 코드 검토 4건의 수정·회귀 검증은 그 대체물이 아니다. API adapter로 전환한 고정 판본과 실제 응답을 확보한 뒤 필요한 material delta를 검토한다.
