# 예측 발행 원장과 누적 평가

## 무엇을 보존하는가

`forecast-records.js`는 실제 생성한 조건부 예측의 입력과 출력에 SHA-256 주소를 부여한다. `issuedAt`은 생성·보존한 시각이며 공개 배포를 입증하는 시각은 아니다. `firstPublishedAt`은 원장에서 항상 `null`이고 공개 여부는 별도의 publication manifest로 연결한다.

두 종류를 구분한다.

- `issued`: 바로 전 완료 UTC 일말을 기준으로 그 다음 UTC 날짜에 실제 생성·보존한 결과.
- `reconstructed`: 현재 확보한 자료·모델로 다시 계산한 회고 결과. 파일을 오늘 보존했다고 당시 발행된 예측이 되지 않는다.

명목 30·90·180일은 마지막 관측 일말부터의 기간이다. 평가 행의 `actualLeadDays`는 생성시각부터 실제 목표 일말까지의 기간이고 `issueLagDays`는 마지막 일말에서 생성까지의 지연이다. 오래된 기준일을 새로운 30일 실시간 발행처럼 저장하면 생성·검증 함수가 거부한다.

## 저장 구조

```text
dist/data/forecast-ledger/
  index.json
  evaluation.json
  experiments.json
  snapshots/<sha256>.json
  records/<sha256>.json
```

인덱스는 작은 목록이다. 화면은 선택한 기록과 스냅샷을 필요할 때 읽는다. 단일 HTML에는 같은 객체를 `atlas-forecast-ledger` JSON element로 포함할 수 있다. 브라우저의 개인 저장소에만 의존하지 않는다.

스냅샷은 관측 행, 출처·단위·가격 정의, 원응답 해시, 실제 수집시각을 보존한다. 공급원 공개시각을 확보하지 못하면 `availableAt:null`과 `provider-publication-time-unknown`을 남긴다. `observedAt`은 UTC 밀리초로 정규화하고 원래 수집시각 문자열도 보존한다. 과거 공급원 판본을 소급 확보했다는 주장은 하지 않는다.

기록에는 다음이 들어간다.

- 입력 스냅샷 ID와 가격 내용 해시.
- 실제 모델 소스 커밋 및 전이 의존 모듈별 해시.
- 모델 버전, 가정, seed, 표본 수, 관측·연구 기준일.
- 고정된 일별 출력과 출력 해시, 목표 기간과 독립 기준선.
- 이전 기록을 수정하는 경우 그 ID와 수정 이유.

`runKey`는 가격 내용, 모델의 실제 소스 해시, 가정, 시나리오, 연구 기준일과 기록 종류를 묶는다. 수집 메타데이터만 바뀌거나 자료 커밋·실행 시각만 바뀌어도 동일 계산은 중복 저장하지 않는다. 같은 `runKey`에서 다른 출력이 나오면 오류로 중단한다. 수정된 계산은 새 ID로 저장하고 이전 파일은 유지한다.

콘텐츠 해시는 내용 일치 검증이며 출처에 대한 전자서명이나 예측 정확도의 증명이 아니다.

## 공개 보존 간격과 저장량

기본 공개 보존 정책은 `preserved-forecast-cadence-1`이다. 첫 실제 생성본은 바로 보존하고, 같은 모델·설정은 직전 실제 보존 기준일 이후 **새로운 완료 관측 행 30개**가 쌓였을 때 다시 보존한다. 달력상의 30일이나 매월 같은 날짜를 뜻하지 않는다. 빠진 관측일은 채우거나 센 것으로 간주하지 않는다. 한 번의 보존은 기본 다섯 경제 가정의 전체 일별 경로와 원본 입력을 저장한다. 경로를 줄이거나 손실 압축하거나 과거 기록을 삭제하지 않는다.

다음 변화는 간격을 기다리지 않고 새 내용 주소 기록을 만든다.

- 실제 모델 소스 해시 또는 모델 버전 변경. 자료 커밋 ID만 달라지는 경우는 제외한다.
- 가정·seed·표본 수 등 계산 설정 변경. 날짜에 따라 이동하는 `asOf`와 `referenceDate`만 설정 비교에서 제외한다.
- 이미 보존한 것과 같은 기준일의 입력 내용 정정. 수집 메타데이터만 바뀌고 가격 내용이 같으면 동일 실행으로 남긴다.

정정과 모델·설정 변경에는 이전 기록과 수정 이유를 연결한다. 이전 파일과 이전 예측의 평가는 유지한다. 기존 `runKey`가 이미 있으면 같은 실행을 다시 추가하지 않는다. 예외 발행 이후 다음 정기 간격은 가장 최근 실제 보존 기준일부터 센다. 같은 날짜의 정정은 기준일 자체를 바꾸지 않는다. 회고 재구성은 명시적인 별도 작업이며 실제 보존 간격을 미루지 않는다.

완료 관측이 오래된 경우에는 위 예외보다 최신성 검사가 먼저 적용된다. 모델이 바뀌었거나 입력이 정정되었더라도 오래된 기준일을 오늘의 실제 발행으로 바꾸지 않는다.

매일의 관측·평가·활성 실험 갱신은 계속한다. 새 기록이 필요 없는 날에는 `index.refresh.outcome`이 `retained-not-due`이며 다음 정보를 남긴다.

```json
{
  "publicationPolicy": {
    "version": "preserved-forecast-cadence-1",
    "intervalObservationDays": 30,
    "basis": "completed-observation-rows",
    "scope": "scheduled-public-preservation",
    "capturesInteractiveCalculations": false
  },
  "lastPreservedAsOf": "2026-10-25",
  "observationDaysSinceLast": 0,
  "nextEligibleAsOf": "2026-11-24",
  "nextEligibleAsOfIsEarliest": true,
  "outcome": "retained-not-due",
  "publicationReasons": ["interval-not-reached"]
}
```

`nextEligibleAsOf`는 앞으로 관측이 매일 확보된다는 조건에서 가장 이른 정기 보존 날짜다. 결측·공급원 지연이면 뒤로 미뤄질 수 있고 모델·설정·입력 정정 예외이면 앞당겨질 수 있다. `publicationDue`는 해당 실행을 시작할 때의 발행 판단이다. 실제 생성 직후에는 마지막 보존일·남은 간격을 새 기록 기준으로 갱신한다. 이 원장은 **정기 공개 보존본**이며 사용자가 브라우저에서 계산하거나 설정을 바꾼 모든 결과를 수집한 활동 기록이 아니다.

2026-10-26 실제 생성한 `ba28c25a0580890636d7b97d00183ef671174d0a` 모델의 다섯 2050년 경로는 5,012,108바이트, 공유 입력 스냅샷은 189,547바이트였다. 평가·실험·인덱스를 합한 당시 원장 전체는 5,927,774바이트였다. 파일 바이트를 직접 읽어 측정한 저장량이며 실행시간 벤치마크가 아니다. 같은 크기의 불변 묶음을 매일 추가한다고 단순 환산하면 365회에 1,898,604,075바이트가 된다. 첫 묶음 이후 365개의 새 일별 관측에서 정기 추가는 12회이므로 같은 크기를 가정한 추가량은 62,419,860바이트다. 모델·설정 변경과 정정의 예외 발행, 향후 파일 크기 변화, Git 압축·이력과 매일 바뀌는 평가·실험 파일의 저장량은 이 환산에 포함하지 않았다. 장기적으로 커지는 원장에 대한 별도 저장 예산 관리는 여전히 필요하다.

## 실행과 CI 연결

모델 및 실험 코드가 실제 커밋된 뒤 실행한다. 생성기는 해당 소스 의존 그래프가 수정된 상태면 거부한다.

```sh
node scripts/build-forecast-ledger.mjs --experiments
node scripts/build-forecast-ledger.mjs --check
node --test tests/forecast-ledger.test.mjs
```

첫 명령은 공개 보존 간격·예외에 해당하는 새로운 계산만 추가하고 현재 자료까지 평가한다. 일별 갱신도 `--experiments`를 함께 사용하는 것이 명확하다. 새 기록을 추가하지 않는 날에도 이미 활성 실험 보고서는 자료·모델·실험 소스·정책 변경을 감지해 옵션이 생략되어도 다시 계산한다. 실제 발행 시각은 실행 시각이며 1시간을 넘겨 과거로 지정할 수 없다. 회고 작업에는 `--kind reconstructed`를 사용한다.

자료가 바로 전 UTC 일말보다 오래되면 작업을 중단하거나 회고본을 실제 발행본으로 만들지 않는다. 새 발행을 건너뛰고 기존 원장을 유지·평가하며 인덱스의 `refresh.outcome`을 `retained-stale-observations`로 표시한다. 기대 기준일과 사용 중 관측 기준일도 함께 남긴다.

`--check`는 과거 기록의 모델 커밋을 현재 HEAD와 같게 요구하지 않는다. 기록·스냅샷의 전체 해시와 연결, 기준선, 현재 자료에 맞는 채점 결과, 실험 결과의 결정적 재생을 확인한다. 보존 정책이 있는 인덱스는 관측 수·마지막 실제 보존일·다음 정기 보존일도 실제 원장과 비교한다. 현재 비교 결과인 실험 보고서는 현재 커밋된 모델·실험 의존 그래프의 실제 파일 해시와도 일치해야 한다. 시간이 지났다는 이유로 예전 기록을 다시 쓰지 않는다. 실험을 포함한 검증은 실제 모델을 다시 실행하므로 단순 JSON 검사보다 시간이 걸린다.

쓰기 잠금은 동시 작성자를 거부한다. 내용 주소 파일은 배타 생성하며 다른 바이트로 덮어쓰지 않는다. 파일을 먼저 완성한 후 인덱스를 교체한다. 공개 묶음의 일관성은 상위 publication manifest와 검증 후 배포 단계에서 관리한다. 중단으로 생긴 미참조 파일은 공개 인덱스에 나타나지 않는다.

## 브라우저 API

```js
const index = await loadForecastIndex();
const entry = index.entries.at(-1);
const record = await loadForecastRecord(entry);
const snapshot = await loadForecastSnapshot(entry);
await verifyForecastRecord(record, snapshot);
const path = restoreForecastPath(record);
const evaluation = await loadForecastEvaluation();
const experiments = await loadForecastExperiments();
```

로더에는 `signal`, `fetchImpl`, `baseUrl`, `embedded`를 주입할 수 있다. `embedded`의 구조는 `{index, records:{[id]:record}, snapshots:{[id]:snapshot}, evaluation, experiments}`다. 파일 경로는 콘텐츠 ID와 정확히 일치해야 한다. 외부 경로나 `../` 경로를 받아 읽지 않는다.

`compareForecastRecords(before,after)`는 공통 목표 날짜에서 로그가격 변화를 기준선·주기 성분·잔차·잔여항으로 정확히 분해한다. 원인들이 같은 자료 변화에 영향을 받을 수 있으므로 인과 기여도로 해석하지 않는다.

## 채점과 표본 수

`forecast-evaluation.js`는 만기가 지난 실제 관측이 있는 목표만 채점한다. 아직 미래이면 `pending`, 날짜가 지났지만 해당 종가가 없으면 `missing-observation`, 회고 재구성이면 `retrospective`다. 결측을 보간해 채점하지 않는다. 미래의 잘못된 가격은 고정 cutoff 이후라면 평가와 입력 해시에서 제외한다.

비교 기준선은 현재 가격 유지와 축소 로그추세다. 추세는 이전 최대 180일 로그 변화를 25%로 축소하고 연간 로그 변화율을 ±log(2)로 제한한다. 이는 사전에 고정한 실험 가정이며 최적화 결과가 아니다. 발행 때 계산한 기준선을 기록에 고정한다.

점수는 시나리오·기간·모델 소스 해시·기준선 버전별로 묶는다. 서로 다른 모델 소스의 성적을 합쳐 하나의 성능으로 주장하지 않는다. 원시 행의 가격 오차와 기준선 오차를 함께 보존한다. 출력 밴드는 경제 가정 범위이므로 확률구간 점수를 붙이지 않는다.

평가에는 기록 수, 발행 수, 고유 기준일, 서로 다른 목표 날짜, 중첩 여부가 있다. `independentSampleSize`는 `null`이다. 여러 시나리오와 겹친 기간을 독립적인 시장 실험으로 세지 않는다. 30일 채점이 쌓였다고 3년·2050년 경로의 예측력이 검증되는 것은 아니다.

## 고정된 조건부 실험

`forecast-experiments.js`에는 이번 릴리스에서 버전과 해시를 부여한 정책이 있다. 정책은 개발 중 확정되었으며 역사 자료를 보기 전에 사전 등록한 실험이나 완전히 미접촉한 holdout이라고 주장하지 않는다.

1. 730일 이후부터 28일 간격 기준일로 현재 가격 유지·축소 추세·변동성에 따라 더 축소한 추세를 비교한다.
2. 30·90·180일 각각을 채점하고, 전체 행과 결과 구간이 겹치지 않는 부분집합을 구분한다.
3. 구간 후보는 해당 기준일까지 결과가 확정된 이전 오차만 사용한다. 겹치지 않는 목표 구간을 선택하고 최소 12개가 없으면 산출을 보류한다.
4. 포함률과 로그 구간 폭·구간 점수를 함께 비교한다. 단순 기준 구간은 이전 180일 변동성과 고정된 정규분포 분위수를 사용한 별도 가정이다.
5. 공개된 평가 가정이 존재한 이후의 월말에서 현재 보정 시계·고정 시계·주기 변위 제거를 비교한다. 주기 변위를 제거한 경로는 동일 잔차를 공유하는 성분 제거 실험이며 독립 학습 모델이 아니다.

가격 후보의 회고 관문은 겹치지 않는 결과 구간 30개 이상, 두 기간 이상에서 두 단순 기준선 중 더 나은 것보다 로그 오차 5% 이상 개선이다. 이 관문을 통과해도 발행 후 평가가 없으면 채택하지 않는다. 구간 실험도 개별 사건의 확률이나 조건부 포함률을 보장하지 않는다. 3~5개월 사이클 조기화의 일반 법칙을 검증했다는 주장은 하지 않는다.

2026-10-25까지의 저장 자료로 실제 실행한 개발 검토에서는 순차 평가 549행, 주기 성분 비교 26행이 생성되었다. 변동성 추세 후보는 회고 관문을 통과한 기간이 0개였고, 구간 후보의 로그 구간 점수는 세 기간 모두 단순 변동성 구간보다 나빴다. 따라서 기존 모델·시계·경제 가정 범위를 자동 교체하지 않았다. 최종 숫자와 소스 신원은 생성된 `experiments.json`이 정본이다.

## 검증 근거와 범위

`tests/forecast-ledger.test.mjs`는 실제 장기 엔진의 2050년까지의 출력 보존, 내용 변조, 늦은 발행, 이전 발행본 불변성, 회고/실제 생성 구별, 결측, 독립 기준선, 단일 HTML 로더, 시간 누수와 중첩 보정 오차를 검사한다. 개발 중 동일 실행의 출력 충돌 무시·미래 행이 평가 해시에 섞임·서로 다른 소스 모델 성적의 합산을 먼저 실패로 재현한 후 수정했다.

공개 보존 간격의 추가 회귀는 처음 보존, 29개와 30개 관측, 연도 경계·윤일·결측, 소스 커밋과 실제 소스 해시의 구별, 설정 변경, 같은 기준일의 정정, 최신성 우선순위, 회고 기록의 분리, 미발행일의 평가 갱신을 검사한다. 기존 24개 통과·새 7개 실패를 확인한 뒤 수정하여 31개 모두 통과했다. 실제 다섯 기록과 스냅샷의 복사본에서도 미발행 갱신 후 전체 검증·실험 재생을 통과했으며 여섯 불변 파일의 바이트와 원본 파일은 모두 유지되었다.

이 검사는 금융 시장의 미래 결과를 증명하지 않는다. 정형 상태 검증, 계산 재현성, 통계적 평가, 공개 배포 증거는 각각 별도의 범위를 가진다.
