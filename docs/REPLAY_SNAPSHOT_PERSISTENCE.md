# 현재 예측선의 저장·복원

## 사용자에게 보이는 동작

현재 예측선 고정 모드는 재생을 시작할 때 화면에 있던 노란/주황 점선, 갈색 범위와 사이클 주석을 별도 복사본으로 고정한다. 실제 봉은 선택한 날짜 직전까지 보이고, 선택한 날짜부터 하루씩 공개한다. 주봉에서는 공개된 실제 Bitstamp 일봉만으로 같은 주봉을 갱신한다. 기존 중앙 막대와 Select bar 네 가지 시작 동작은 바꾸지 않는다.

종료 창에서 현재 세션 저장을 체크하고 종료하면 예측 경로·범위·표시 문맥까지 저장한다. 이후 현재 모델이나 시장 자료가 갱신돼도 Continue는 저장된 경로를 사용한다. Start new는 새 진입 시점의 현재 화면을 캡처한다. 선택·취소·속도·간격 변경만으로 기존 저장을 덮어쓰지 않는다.

이 모드는 현재 가정과 실제 관측의 시각 비교다. 2026-10-21은 기본 재생 시작 제안일이지 현재 가정의 발행일이 아니다. 발행 시각을 소급하거나 성적·적중률을 표시하지 않는다. Replay Trading·주문·브로커 기능도 추가하지 않는다.

## 상태와 정보 경계

- `captureReplayView`는 첫 비동기 자료 요청 전에 표시된 입력·경로·표시 설정을 복사하고 깊게 동결한다. 이후 실시간 화면의 원본 객체 변경이 유입되지 않는다.
- `sealReplaySnapshot`은 확정한 세션의 경로, 입력, 주석, 원점, 원래 캡처 시각과 엔진 출력 해시를 묶는다. 이 준비 단계는 저장소에 쓰지 않는다.
- `restoreReplaySnapshot`은 저장된 원점·출력 해시·전체 JSON의 SHA-256을 확인한다. 이어서 실제 엔진이 저장된 경로의 출력 해시를 다시 검증한다. 손상된 저장본을 현재의 새 경로로 조용히 대체하지 않는다.
- 캡처 시각 `createdAt`은 유지한다. 실제 관측을 사용할 수 있는 시각 `evaluatedAt`은 재개 시점이다. 이 둘을 혼동해 이후 확보한 실제 봉을 차단하지 않는다.
- 공개 평가 JSON에는 현재 공개된 프레임과 캡처 식별자만 들어간다. 전체 저장 입력 자료를 내보내기에 붙이지 않는다.
- 저장 JSON의 상한은 8 MiB다. 브라우저 자체 할당량은 더 작을 수 있다. 크기·할당량·권한 오류 시 저장을 완료했다고 표시하지 않고 기존 저장을 유지한다.

SHA-256은 로컬 저장값의 변경 탐지를 위한 것이다. 제3자 발행 기록, 제공자 인증, 당시 사용 가능성 또는 예측 정확도를 증명하지 않는다.

## 기존 저장본

v1.29.6 이전의 해시 전용 세션은 현재 모델의 출력 해시가 일치할 때만 기존 방식으로 재개한다. 성공적으로 재개한 뒤 사용자가 저장을 선택하면 전체 캡처를 포함한다. 과거 경로 자체가 저장되지 않았고 현재 모델과 해시도 다르다면 해당 경로를 복원할 수 없다고 알린다. 다른 경로로 바꾸거나 기존 저장을 지우지 않는다.

## 재실행할 검사

```sh
node --test tests/chart-replay-snapshot.test.mjs tests/chart-replay-ui.test.mjs
npm run verify:chart-replay
npm test
```

실제 엔진을 쓰는 새 저장 검사와 기존 코디네이터의 결정적 UI 검사 범위를 구분한다. UI 검사에는 DOM·자료 로더·렌더러 대역이 있으므로 네이티브 브라우저 검증이라고 부르지 않는다. 기존 전체 브라우저·Hallmark·출판 검사는 별도로 실행한다.

변경 전 코디네이터로 신규 Continue 검사를 실행하면 `explicit save must keep the entire curve, not only an output hash`에서 실패한다. 변경 후 관련 로컬 검사 120개가 통과했다. 전체 로컬 검사 2,235개 중 30개는 Git 이력 없는 소스 압축본에서 Git 기반 출처 확인을 실행해 실패했으며, 이 결과를 전체 통과로 취급하지 않는다. 최종 원격 CI와 배포 여부는 PR 실행 기록으로 확인한다.
