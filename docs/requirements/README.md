- 위 세 요구 문서의 보안 최소선·수용 기준·명시적 구현 보류를 보존한다. 구현에 필요한 미결정 항목은 별도로 확정하며, 문서 정리 완료를 구현 완료로 읽지 않는다.

- 3열 AI 채팅은 인증 체계(역할)와 연동해 노출 범위를 정한다.

## 개발 우선순위 (2026-11-12 재정리)

| 순위 | 항목 | 이유 | 시작 조건 |
|---|---|---|---|
| **P0** | 최종 자산 잠금 + 차트 마감 | WP-A의 유일한 선행 조건이고, 차트는 h1 계약만 풀면 배포 가능 | `yyOkfU0FkYzNPO8f` 세션의 최종 PDF/PPTX 해시·페이지 수 확정(`deck-lock.json`), Pro의 h1 패치 |
| **P1a** | WP-A 화면 골격 — 장표 중심 + 하단 중앙 컨트롤 | 잠금 전에도 목업·구조·접근성 명세·스키마 검증기는 만들 수 있다. 데모의 뼈대가 먼저 서야 잠금 후 작업이 짧아진다 | 없음(A-5 개정 계약) |
| **P1b** | WP-A 타임라인·플레이어·동기화 | 실제 덱 좌표·페이지 번호·배포 패키지는 잠금 뒤에만 만든다 | P0 잠금 완료 |
| **P2** | 리브랜딩 + 스카우트 표면 | 이름·도메인·README·케이스 스터디. P1 데모가 있어야 설득력이 생김 | P1 데모 동작 |
| **P3** | 릴레이 3열 + RAG | 제품 차별점이지만 서버·유료 저장소가 필요 | Vectorize+D1 생성 승인 |
| **P4** | 인증·비공개 | 유료 구독·초대 운영의 전제 | 데이터 모델·미결정 4건 확정 |
| **P5** | 시즌 테마 | 장식 레이어. 다른 항목을 막지 않음 | 없음(언제든) |

우선순위는 "지금 할 수 있는가"가 아니라 "다음 항목을 막고 있는가"로 정했다. P0가 비어 있는 동안 P1의 타임라인 작업을 시작하지 않는다.

문서 이관은 인증·유료 RAG·테마 구현 승인이나 기존 미결정 조건의 해제를 뜻하지 않는다.
