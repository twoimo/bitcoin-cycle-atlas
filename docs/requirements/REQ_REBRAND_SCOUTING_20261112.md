# 요구사항 — 프로젝트 리브랜딩 + 플스포컴퍼니 스카우트 대응 (초안)

작성 2026-11-12. 상태: **요구사항 확정 대기**(이름·도메인 미결정). 대상 저장소 `twoimo/bitcoin-cycle-atlas`.

## 1. 목표

- 저장소명과 도메인을 **대한민국 사람이 읽는 즉시 "메타인지"가 연상되는** 형태로 바꾼다.
- 플스포컴퍼니(김동호)가 프로젝트를 보고 **스카우트 문의를 하고 싶게** 만드는 공개 표면(README·데모·케이스 스터디)을 갖춘다.
- 기존 배포·검증 게이트·문서 링크를 깨지 않는다. 이름 변경은 제품 개선보다 위험이 크므로 단계와 되돌림을 먼저 정한다.

### 2.1 시사점

1. 그의 브랜드 언어가 곧 **메타인지**다. 우리 이름도 메타인지 계열이어야 설명이 필요 없다.
2. 그가 가르치는 것(사이클·심리·손익비·차트·복습)을 제품이 실제로 보여줘야 한다. 특히 **컨퍼런스 복습(발표+자막 싱크)** 은 "강의를 다시 보는 방식"을 제품으로 증명하는 장면이다.
3. 스카우트 판단 근거는 화려한 데모보다 **검증된 완성도**다. 로컬 게이트·재현 가능한 수치·문서화된 한계가 곧 포트폴리오다.

## 3. 네이밍

기준: 한글 2~4글자, 읽는 즉시 메타인지/투자 지도가 연상, 저장소는 소문자 영문, 도메인은 `.kr` 우선.

| 후보 | 저장소 | 도메인 | 장점 | 위험 |
|---|---|---|---|---|
| 메타차트 | `metachart` | `metachart.kr` | "메타+차트"가 즉시 이해되고 짧음 | '차트'가 기능을 좁혀 보임 |
| 메타사이클 | `metacycle` | `metacycle.kr` | 사이클 자산과 직결, 확장 여지 | 메타인지 연상은 약함 |
| 메타인지차트 | `metacognition-chart` | `metacognition.kr` | 브랜드 직결, 설명 불필요 | 김 |
| 생각지도 | `thinkmap` | `thinkmap.kr` | 한국어 친화, 메타인지의 번역에 가까움 | 투자 연상이 약함 |

권장: **1안 메타차트**(저장소 `metachart`, 도메인 `metachart.kr`), 차선 2안 메타사이클. 도메인 가용성은 등록기관 검색과 장바구니로만 확정한다(WHOIS 부재는 가용 근거가 아니다).

## 4. 마이그레이션 계획

현재 결합도(2026-11-12 실측):

- 저장소명 문자열 참조 **585개 파일**, `/bitcoin-cycle-atlas` basePath 참조 **533개 파일**
- Cloudflare Worker 2개: `bitcoin-cycle-atlas`(정적), `bitcoin-cycle-atlas-models`(모델)
- 운영 origin: `https://bitcoin-cycle-atlas.twoimo.workers.dev`
- 기준 파일: `ops/cloudflare-scheduled-builds.json`, `cloudflare.config.ts`, `dist/publication.json`

단계:

1. 이름·도메인 확정과 등록(사용자 결정).
2. GitHub 저장소 rename. 구 경로 리다이렉트가 유지되는지 확인.
3. Cloudflare에 새 도메인을 **추가**하고 구 도메인과 병행 운영.
4. basePath 전환: `publication.json`, 정적 자산 경로, 문서·스크립트 참조를 한 번에 바꾸지 말고 **별도 커밋**으로 나눈다.
5. 문서·스크립트의 저장소명 참조 갱신(585개), 깨진 링크 0 확인.
6. 구 URL → 새 URL 301 확인 후 구 도메인 제거.
7. 게이트 재실행: `npm test`, `verify:static`, `verify:pages`, compare·반응형·WP6·chart-qa.

금지: 한 커밋에서 저장소명·basePath·Worker 이름을 동시에 바꾸기, 검증 없이 구 도메인 제거, 진행 중 브랜치의 배포 파이프라인을 이름 변경으로 끊기.

## 5. 스카우트 대응 산출물

- **README 첫 화면**: 한 줄 정의, 3분 데모 링크, 검증 게이트 결과 요약, 연락처.
- **케이스 스터디 1장**: 문제 → 접근 → 검증 방법 → 결과 수치 → 한계.
- **데모**: 컨퍼런스 복습(장표+자막 싱크)과 차트(관측/가정 구분) 두 장면.
- **연락 CTA**: 스카우트 문의용 공개 이메일 1개. 비공개 데이터·고객 정보는 넣지 않는다.
- 금지: 미검증 수치, 과장된 표현, 실제로 하지 않은 사용자 수·매출·성과.

## 6. 수용 기준

| # | 기준 | 측정 |

| S-1 | 이름·도메인 확정이 문서에 기록됨 | 이 문서 개정 + 결정 커밋 |
| S-2 | GitHub rename 후 구 저장소 URL이 리다이렉트됨 | `git ls-remote`·웹 확인 |

| S-5 | 3분 데모가 새 도메인에서 재생됨 | 브라우저 실측 |
| S-6 | README의 연락 CTA가 실제 수신 가능한 주소 | 수신 테스트 1회 |

## 7. 미결정(사용자)

1. 최종 이름과 도메인(1안/2안/기타)
2. 도메인 등록 주체·비용, `.kr`과 `.com` 동시 등록 여부
3. GitHub 개인 계정 유지 vs 조직(org) 이동
4. 데모 공개 범위(전체 공개 / 비밀번호 보호 / 링크 공유)

## 8. 우선순위에서의 위치

이 문서는 **P2**다. P0(최종 자산 잠금·차트 마감)과 P1(컨퍼런스 복습 페이지)이 먼저다. 이름 변경은 배포·검증 경로를 건드리므로, P1 데모가 동작한 뒤에 하는 편이 안전하다. 단, README·케이스 스터디 문안은 P1과 병행해도 된다.
