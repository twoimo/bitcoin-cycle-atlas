# 요구사항 — 릴레이 콘텐츠 3열 레이아웃 + RAG AI 채팅 (초안)

작성 2026-11-09. 상태: **요구사항 정리 단계(구현 전)**. 대상 저장소 `twoimo/bitcoin-cycle-atlas`.

## 1. 목표
- 릴레이 콘텐츠 화면을 **3열**로 재구성한다.
  - 1열: 소스 목록(소수의견, 인생의 방, 모바일한경 등) — 지금과 동일한 분류·탐색
  - 2열: 선택한 소스의 채팅/메시지 본문
  - 3열: 2열 오른쪽의 **AI 어시스턴트 채팅창**
- 3열 AI는 **현재 릴레이 콘텐츠 전체를 근거로 RAG** 답변을 한다. 근거 없는 추측 대신 인용을 붙인다.
- OpenAI API를 사용하며, 키는 서버측에서만 사용한다.

## 2. 레이아웃 계약
| 구간 | 폭(데스크톱) | 내용 |
|---|---|---|
| 1열 | 240–280px | 소스 그룹·채널·최근 수집 시각 |
| 2열 | 가변(flex) | 메시지 스레드, 사진·앨범·링크 프리뷰, 원문 링크 |
| 3열 | 360–420px | AI 채팅: 입력창, 스트리밍 답변, 인용 칩, 대화 초기화 |

- 1024px 이하: 3열을 **드로어/모달**로 전환(2열 유지).
- 768px 이하: 1열을 드로어로, 2·3열은 탭 전환.
- 스크롤 소유자 규칙: 각 열이 독립 스크롤, 페이지 전체 세로 스크롤 없음(짧은 화면 예외).

### 2.1 1열·3열은 접이식 (필수)
1열(소스 목록)과 3열(AI 채팅)은 **각각 독립적으로 접고 펼 수 있어야** 한다. 2열(대화 본문)은 상시 표시이며, 접힌 열의 공간을 흡수해 넓어진다.

| 상태 | 1열 | 2열 | 3열 |
|---|---|---|---|
| 기본(1440↑) | 펼침 240–280px | 가변 | 펼침 360–420px |
| 1열 접힘 | 0px(토글만 남김) | 흡수해 확장 | 유지 |
| 3열 접힘 | 유지 | 흡수해 확장 | 0px(런처 버튼만) |
| 둘 다 접힘 | 0px | 전체 폭(읽기 폭 상한 1,040px 중앙 정렬) | 0px |

**토글 위치**
- 1열: 1열 헤더 우측에 접기 버튼(`aria-label="소스 목록 접기"`). 접힌 뒤에는 2열 좌측 상단에 얇은 열기 버튼(`소스 목록 열기`)을 남긴다.
- 3열: 3열 헤더 좌측에 접기 버튼(`aria-label="AI 채팅 접기"`). 접힌 뒤에는 우측 하단에 44px 런처 버튼(`AI 채팅 열기`)을 띄운다.
- 두 버튼 모두 44×44px 이상, `aria-expanded`와 `aria-controls`로 연결.

**상태 기억**
- `localStorage` 키 `atlas-relay-columns` = `{ left: boolean, right: boolean }`. 새로고침·페이지 이동 후에도 유지.
- 공유 링크용 URL 파라미터 `?relay-cols=right`(접힌 열 목록)도 지원하고, URL이 있으면 저장값보다 우선한다.
- 첫 방문 기본값: 1440↑ 둘 다 펼침, 1024–1439는 3열 접힘, 768 이하는 드로어 모드.

**키보드·접근성**
- `[` 로 1열, `]` 로 3열 토글(입력창에 포커스가 있을 때는 동작하지 않음).
- 접을 때 포커스가 사라지지 않도록 토글 버튼으로 포커스를 옮긴다. 펼칠 때는 해당 열의 첫 포커스 요소로 이동.
- `prefers-reduced-motion`이면 폭 전환 애니메이션을 끈다(즉시 전환).
- 스크린리더: 상태 변경 시 `aria-live="polite"`로 "소스 목록 접힘" 안내.

**저장 내용 보존**
- 3열을 접어도 **대화 스레드·입력 중인 초안·스트리밍 응답은 유지**한다(숨김만 하고 상태는 파괴하지 않음).
- 1열을 접어도 스크롤 위치·선택한 채널을 유지한다.
- 스트리밍 중 접기는 응답을 중단시키지 않는다. 다시 펼치면 이어서 표시.

**전환 규칙**
- 폭 애니메이션 160ms(모션 최소화 시 0ms), 레이아웃 시프트로 스크롤 앵커가 튀지 않아야 한다.
- 접힌 열이 포커스를 포함하면 접기 전에 포커스를 토글로 이동한다.

## 3. RAG 파이프라인
1. **수집**: 텔레그램(소수의견 등)·네이버(인생의 방)·모바일한경 릴레이 번들. 현재 파이프라인 결과를 그대로 사용.
2. **정규화**: 채널·발신자·수집시각·원문 URL·본문 텍스트·첨부 메타를 표준 레코드로.
3. **청킹**: 400~800 토큰, 15% 오버랩. 제목·날짜·채널을 청크 메타로 보존(인용에 사용).
4. **임베딩**: OpenAI 임베딩 모델(기본 `text-embedding-3-large`, 비용 제약 시 `-small` + 차원 축소). 청크 해시로 중복 임베딩 방지.
5. **저장**: 벡터 저장소 선택지 — Cloudflare Vectorize / D1(메타) / 외부 pgvector. 저장 위치는 배포 환경 제약과 비용으로 결정하고 문서화.
6. **검색**: 하이브리드(BM25 + 벡터) → 상위 후보 30 → 리랭크 → 상위 6~8 청크. 최신성 가중(최근 N일 부스트).
7. **생성**: 낮은 temperature(≤0.3), 시스템 프롬프트에 "제공된 근거만 사용, 근거 없으면 없다고 답변" 명시. 인용은 `[n]` 형식 + 원문 링크.
8. **후처리**: 인용 검증(답변에 인용된 청크가 실제 검색 결과에 존재하는지), 민감정보 마스킹.

## 4. OpenAI API 사용 규칙
- API 키는 **서버 측 시크릿**(Cloudflare Workers secret)으로만 보관. 클라이언트 번들·응답·로그에 노출 금지.
- 사용자별·IP별 레이트 리밋과 **일일 토큰 예산** 상한을 둔다.
- 스트리밍 응답, 요청·응답 토큰 수를 저장해 비용을 집계한다.
- 모델은 용도별로 분리(임베딩 / 생성), 변경 시 비용·품질 재측정.
- 공식 문서 기준으로 임베딩·검색·평가 모범 사례를 확인하고 선택 이유를 기록한다.

## 5. 대화 저장
```
ai_threads(id, user_id, title, created_at, updated_at)
ai_messages(id, thread_id, role, content, citations_json, tokens_in, tokens_out, latency_ms, model, created_at)
ai_feedback(message_id, user_id, score, note, created_at)
```
- 대화는 사용자별로 격리하고, 검색 컨텍스트에 다른 사용자의 대화를 넣지 않는다.
- 인용 청크 ID와 스냅샷 해시를 저장해 나중에 근거를 재확인할 수 있게 한다.

## 6. 평가 메트릭
### 검색
- `Recall@k`(k=5,10), `nDCG@10`, `MRR`
- 최신성 정확도: "최근 N일" 질문에서 실제 최신 문서가 상위에 오는 비율

### 생성
- `Faithfulness`(답변 문장이 근거로 뒷받침되는 비율)
- `Answer relevance`(질문-답변 관련성)
- `Citation precision / recall`(인용한 근거가 실제로 답을 뒷받침하는가)
- `No-answer correctness`(근거가 없을 때 "없다"고 답하는 비율)

### 운영
- 지연 p50/p95, 첫 토큰 지연, 토큰/비용 per query, 오류율, 사용자 피드백 점수

### 골든셋
- 60~100문항(채널별·주제별·기간별·답 없음 케이스 포함). 각 문항에 정답 근거 문서 ID를 라벨링.
- 릴리스마다 자동 실행, 임계값 미달 시 배포 차단.

| 메트릭 | 최소 기준(제안) |
|---|---|
| Recall@10 | ≥ 0.85 |
| nDCG@10 | ≥ 0.70 |
| Faithfulness | ≥ 0.90 |
| Citation precision | ≥ 0.90 |
| No-answer correctness | ≥ 0.85 |
| p95 지연 | ≤ 6s(스트리밍 첫 토큰 ≤ 1.5s) |

## 7. QA 시나리오(사용자 유형 × 과업)
| 유형 | 대표 질문 | 기대 |
|---|---|---|
| 신규 사용자 | "이 방에서 최근 무슨 얘기 했어?" | 최근 소스 요약 + 인용 |
| 리서처 | "금리 관련 언급만 모아줘" | 주제 필터 검색, 인용 다수 |
| 투자자 | "이 주장의 근거 원문 보여줘" | 원문 링크·발언 시각 |
| 검증자 | "상충되는 두 의견 비교해줘" | 양측 인용, 판단 유보 |
| 운영자 | "지난주 수집 실패한 채널?" | 자료 없음 응답 정확 |

실패 모드 점검: 자료 없음, 오래된 자료만 존재, 질문이 여러 채널에 걸침, 첨부 이미지 중심 글, 아주 긴 문서, 릴레이 본문에 포함된 지시문(프롬프트 인젝션) 무시 여부.

### 7.1 접이식 QA 케이스 (1열·3열)
| # | 시나리오 | 기대 |
|---|---|---|
| 1 | 1열 접기 → 2열 확장 | 2열 폭이 접힌 폭만큼 증가, 스크롤 위치 유지 |
| 2 | 3열 접기 → 런처만 표시 | 우측 하단 44px 런처, 클릭 시 펼침 |
| 3 | 둘 다 접기 → 새로고침 | 접힘 상태 유지, 2열 중앙 정렬 |
| 4 | 3열 접은 채 응답 스트리밍 | 응답 계속 진행, 펼치면 이어서 표시 |
| 5 | 3열 접은 채 입력 중이던 초안 | 초안 보존, 펼치면 그대로 |
| 6 | `[`·`]` 단축키 | 각 열 토글, 입력창 포커스 중엔 동작 안 함 |
| 7 | 1024 진입 | 3열 자동 접힘(기본값), 1열 유지 |
| 8 | 768 이하 진입 | 1열 드로어, 2·3열 탭 전환 |
| 9 | 접힌 열이 포커스 포함 | 포커스가 토글로 이동, 포커스 소실 없음 |
| 10 | `prefers-reduced-motion` | 애니메이션 없이 즉시 전환 |
| 11 | URL `?relay-cols=right`로 진입 | 저장값보다 URL 우선 |
| 12 | 스크린리더 | 접힘/펼침 상태가 `aria-live`로 안내 |

## 8. 보안·정직성
- 릴레이 본문은 **데이터**이며 지시가 아니다. 시스템 프롬프트에서 명시하고, 인젝션 시도 문장은 인용만 하고 실행하지 않는다.
- 개인정보(전화번호·계좌·주소) 마스킹 규칙과 로그 보존 기간.
- 답변에는 항상 근거 한계를 표시(수집 범위·기간).
- 비용 상한 초과 시 기능을 잠그고 사용자에게 안내(조용한 실패 금지).

## 9. 수용 기준
1. 3열 레이아웃이 1440·1024·768·390에서 계약대로 동작하고 스크롤 소유자가 명확하다.
1-1. **1열과 3열이 각각 독립적으로 접히고 펼쳐지며**, 접힌 공간을 2열이 흡수한다. 상태는 새로고침 후에도 유지된다.
1-2. 3열을 접어도 대화·초안·스트리밍이 보존되고, 펼치면 이어서 보인다.
1-3. 접기/펼치기 토글이 44px 이상이고 `aria-expanded`·`aria-controls`로 연결되며, 접힘 시 포커스가 사라지지 않는다.
2. AI 답변마다 인용 칩이 있고, 클릭 시 원문 릴레이 항목으로 이동한다.
3. 골든셋 자동 평가가 CI에서 실행되고 임계값을 통과한다.
4. 키 노출 스캔(번들·응답·로그)에서 0건.
5. 자료 없음 질문에서 추측 대신 "근거 없음"을 답한다.
6. 사용자별 대화 격리 테스트 통과.

## 11. 미결정 사항
- 벡터 저장 위치(Vectorize vs 외부 pgvector)와 비용 상한.
- 임베딩 모델 선택(large 3072d vs small + 축소)과 재임베딩 주기.
- 대화 보존 기간과 사용자 삭제권 처리.
- 3열 AI 사용을 로그인 사용자 전체에 열지, 특정 역할에만 열지(1번 요구의 권한 체계와 연동).
